# مخطط SQLite والترحيلات (Migrations)

[English](README.md) · [الخادم](../README.ar.md) · [الإعدادات](../../docs/api/README.ar.md)

تتولى قاعدة بيانات SQLite حفظ البيانات الوصفية، وسجلات المراجعات، والمصادقة، والإعدادات، والمجموعات، والاختبارات التقييمية، وتقدم التعلّم في المتصفح، وبيانات حالة الناشر وتكامل OAuth. تُطبق الترحيلات بتسلسل صارم وموثق ببصمات SHA-256. تبدأ أي قاعدة بيانات جديدة فارغة تماماً دون وجود مالك أو بيانات اعتماد أو ملف شخصي أو محتوى منشور أو ملفات وسائط.

## الملفات والاتصالات والمعاملات

يستخدم تطبيق Go الحزمة القياسية `database/sql` مع مشغل SQLite المكتوب بلغة Go الخالصة (`modernc.org/sqlite` بالإصدار v1.61.0 ومكتبة `libc` v1.79.0 المقابلة له، والمثبتين في ملفي `go.mod` و`go.sum`). بيئة التشغيل تعتمد على Go بالكامل دون الحاجة إلى Node.js أو خادم قاعدة بيانات منفصل. يحتوي المسار المحدد في المتغير `BLOG_DATA_ROOT` على ملف قاعدة البيانات `blog.sqlite` وملفات تسجيل المعاملات في SQLite (`WAL` و`SHM`). يجب أن يكون المسار الحقيقي المعتمد خارج شجرة الكود البرمجي وحزم الإصدارات، وأن يكون خاصاً بصلاحيات `0700` ومملوكاً لحساب خدمة النظام المشغل للتطبيق؛ وتكون قاعدة البيانات وملفاتها المرافقة ملفات عادية خاصة بصلاحيات `0600`. تُنشأ أي مجلدات مفقودة بصلاحيات خاصة تلقائياً، وتُرفض ملفات قاعدة البيانات التي تكون عبارة عن روابط رمزية (symlinks). يتحكم المشغل الموثوق في هذا المجلد وحده، ويُحظر منح صلاحيات الكتابة في أي مجلد أب له لأي مستخدمين آخرين.

يطبق كل اتصال فعلي إعدادات: `foreign_keys=1` و`busy_timeout=5000` ميلي ثانية و`journal_mode=WAL` و`synchronous=FULL` و`trusted_schema=0`. يقتصر تجمع الاتصالات (connection pool) على 4 اتصالات كحد أقصى. تبدأ المعاملات بصيغة `IMMEDIATE` لترتيب عمليات الكتّاب وتفادي التعارضات؛ حافظ على قصر مدة المعاملات، وتجنب فتح معاملة أثناء استقبال رفع الملفات أو معالجة Markdown أو إجراء اتصالات شبكية. تُحدّث دالة `BumpVersion` الجداول المسموح بها برمجياً فقط باستخدام عداد إصدار متوقع داخل المعاملة نفسها المسؤولة عن تعديل المحتوى أو الإعدادات. تعني استجابة صفر من الصفوف المتأثرة وقوع خطأ تعارض الإصدارات `ErrVersionConflict`؛ حيث يتعذر على كاتبين يحملان الإصدار المتوقع نفسه تنفيذ التغييرات بنجاح معاً. يتحقق فحص الجاهزية (readiness) من استجابة SQLite بمهلة ثانية واحدة، بينما تبلغ مهلة تطبيق الترحيلات عند بدء التشغيل 30 ثانية.

تستخدم دالة `NewID` المصدر العشوائي الآمن `crypto/rand` لتوليد معرفات مبهمة بطول 128 بت ممثلة بنظام سداسي عشري صغير (hexadecimal). وتعتمد الطوابع الزمنية توقيت UTC بدقة ثابتة بالميلي ثانية (`2006-01-02T15:04:05.000Z`) وتكون القيم الافتراضية في SQL بتوقيت UTC دائماً. ترفض قيود التحقق أي فروق توقيت محلية أو أوقات مشوهة. كما تُولّد معرفات السجلات الجديدة بواسطة كود Go حصراً، وليس من الروابط اللطيفة (slugs) أو أسماء الملفات التي يرسلها المستخدم أو البيانات الوصفية المرفوعة.

## حدود البيانات وضمانات قاعدة البيانات

| السجلات | ضمانات قاعدة البيانات |
| --- | --- |
| `content_items` / `content_versions` | مفتاح محتوى ثابت وفريد، مع ضمان فريدية الزوج (العنصر/اللغة) والزوج (اللغة/الرابط اللطيف)، واقتصار اللغات على EN/AR/FR فقط، وعداد إصدارات موجب، وثبات الرابط اللطيف بعد النشر الأول |
| `revisions` | مسار نسبي لملف Markdown فريد وثابت، مع بصمة تجزئة وحجم وبيانات وصفية ثابتة؛ وتضمن المفاتيح الأجنبية المركبة بقاء مؤشري المسودة والنشر الحي ضمن الإصدار اللغوي الخاص بهما |
| `collection_items` | موضع ترتيبي موجب وفريد داخل المجموعة، وانتماء العنصر لمجموعة واحدة فقط، وتطابق نوع العضوية (`lesson` لمسارات `learning` و`doc` لمجموعات `docs`)؛ مع ضمان عدم نقل أو اختفاء أي عضوية منشورة |
| `media` وجداول المراجع | مسار نسبي مولد للوسائط مع بيانات البصمة والنوع والحجم؛ وتمنع مراجع المراجعات والإعدادات المحفوظة حذف الوسائط المرتبطة بها |
| `config_documents` / `config_revisions` | نوع فريد للوثيقة، ولقطة ثابتة لكائن JSON محدد النطاق، وإصدارات لمخطط البيانات ولوغاريتم الألوان؛ مع ضمان انتماء المؤشر المطبق لوثيقته الخاصة |
| `owner` / `sessions` / `api_tokens` | سجل مالك وحيد، ومعرفات مجزأة وفريدة لرموز الأسرار، وتواريخ انتهاء وإلغاء، ونطاقات وتصاريح محددة للمجموعات؛ مع منع جلسات الاسترداد من إنشاء جلسة مالك كاملة، وحظر الاعتماد على كلمة المرور وحدها كوسيلة لدخول المالك |
| `idempotency_records` | بصمة تجزئة فريدة للفاعل/العملية/المفتاح، وبصمة لجسم الطلب، ومعرفات وحالة وإصدار محدود للنتيجة؛ دون تخزين الرموز السرية الخام أو نسخ من نصوص الطلبات |

لا تُخزّن نصوص Markdown أو بايتات الملفات المرفوعة في أعمدة قاعدة البيانات مطلقاً. يقتصر كائن JSON الخاص بالإعدادات على بيانات الإعدادات والملف الشخصي وتسميات الواجهة المحددة بدقة؛ بينما تبقى نصوص قسم (نبذة عنا) وكافة المقالات والدروس ووثائق التوثيق ملفات Markdown منفصلة. تفرض خدمات التطبيق التحقق من مخطط البيانات، ومراجعة الترجمة، والصلاحيات، وفحص نوع MIME الفعلي، وحصر الملفات داخل نطاقها المسموح. لا تضمن المفاتيح الأجنبية وحدها وجود الملف الفيزيائي على القرص أو تمنحه وصولاً عاماً. ويجب دائماً كتابة الملفات الثابتة غير القابلة للتعديل وتأكيد وجودها قبل اعتماد بياناتها في قاعدة البيانات.

تُدرج النسخة اللغوية الأولى ومراجعة مسودتها في معاملة واحدة: توليد كلا المعرفين، ثم إدراج النسخة مع مؤشر المسودة، ثم إدراج المراجعة وتأكيد المعاملة. تؤجل المفاتيح الأجنبية الدائرية للملكية حتى لحظة الاعتماد (commit). ويجب أن تحدد عملية النشر المراجعة المطلوبة بدقة مع التحقق من شروط المراجعة وقواعد الوصول في خدمة المحتوى. ويبقى التحقق البرمجي على مستوى التطبيق إلزامياً حتى في حال وجود قيد SQL مطابق. وتشترك خطط المسارات المحددة بالإصدار، وروابط الاختبارات، والتصحيح الخاص على الخادم، وهويات المتصفح، والمحاولات العامة في قيود المعاملات نفسها؛ حيث يؤدي غياب خطط المسار أو استخدام سياسات فتح غير مدعومة إلى حجب متون الدروس ووسائطها.

## إجراءات الترحيل والنسخ الاحتياطي

يحتوي الملف التنفيذي على ترحيلات SQL مرقمة ومضمنة داخله، بدءاً من `0001_core.sql`. يتحقق التطبيق عند بدء التشغيل من تسلسل أرقام الترحيلات وصحة أسماء وبصمات SHA-256 لكل ترحيل مطبق، ثم يطبق ملفات SQL وسجل الترحيلات المعلق داخل معاملة واحدة. ويرفض التطبيق بدء التشغيل في حال وجود جداول سابقة دون أرقام إصدار، أو حدوث تغيير في تاريخ الترحيلات، أو وجود فجوات في الترقيم، أو وجود مخطط أحدث مما يفهمه الملف التنفيذي، أو فساد في قيود المفاتيح الأجنبية. وفي حال فشل تنفيذ أي أمر SQL أثناء الترحيل، يتم التراجع عن الترحيل وسجلاته بالكامل. لا تُعدل أبداً أي ترحيل تم تطبيقه مسبقاً؛ بل أضف ملف الترحيل التسلسلي التالي برقم جديد غير مستخدم.

قبل تشغيل ملف تنفيذي أحدث على بيانات موجودة بالفعل:

1. أوقف كافة مثيلات التطبيق وعمليات الكتابة، وتأكد من توقفها تماماً. احتفظ بالملف التنفيذي السابق، وحزمة بناء الواجهة السابقة، وملف إعدادات المشغل الخاص.
2. خذ نسخة احتياطية من مجلد البيانات **بالكامل** مع بقاء عمليات الكتابة متوقفة. يجب أن تشمل النسخة قاعدة البيانات وملفات WAL/SHM وكافة ملفات Markdown والوسائط المرفوعة، وليس ملف `blog.sqlite` وحده. ضع النسخة الاحتياطية خارج مجلد البيانات الحي واحمِ صلاحيات الوصول إليها.
3. تحقق من صحة النسخة واحتفظ بها حتى يتم التحقق الكامل من استقرار الإصدار الجديد. يفترض المثال التالي على نظام Linux أن المتغير `BLOG_DATA_ROOT` يشير إلى المسار الحقيقي المعتمد وأن جميع الكتّاب متوقفون:

```sh
umask 077
backup="${BLOG_DATA_ROOT}.backup-$(date -u +%Y%m%dT%H%M%SZ)"
cp -a -- "$BLOG_DATA_ROOT" "$backup"
diff -qr -- "$BLOG_DATA_ROOT" "$backup"
```

4. شغّل الملف التنفيذي الجديد مع تمرير متغيرات البيئة الموثقة. عند حدوث أي خطأ في الترحيل، يخرج التطبيق فوراً قبل بدء خادم HTTP. تحقق من سلامة المسار `/readyz` ونتائج اختبارات الإصدار المعنية. للحصول على إجراءات النسخ المتزامن أثناء التشغيل والاستعادة الآمنة لبيانات الاعتماد، اتبع [دليل الاسترداد](../../docs/operations/recovery.md). يُرجى ملاحظة أن إجراء النسخ اليدوي المذكور هنا يتطلب إيقاف كافة عمليات الكتابة أولاً.

لا توجد ترحيلات عكسية للرجوع للوراء (down migrations). لا تشغّل أبداً ملفاً تنفيذياً أقدم على قاعدة بيانات تم ترقيتها، ولا تحذف صفوفاً من سجل الترحيلات لإجبار التطبيق على الإقلاع، ولا تُعطل قيود المفاتيح الأجنبية. وإذا أردت الرجوع لإصدار سابق، فاستعد نسخة احتياطية كاملة مطابقة مع الملف التنفيذي وحزمة البناء والإعدادات المتوافقة في مجلد بيانات منفصل وخاص أثناء توقف الخادم؛ وتحقق من سلامته بالكامل قبل تحويل المسار النشط إليه. وإذا كان الإصدار الأحدث قد استقبل عمليات كتابة بالفعل، فإن الرجوع لنسخة أقدم سيؤدي إلى فقدان تلك التعديلات اللاحقة؛ لذا خطط لإصلاح المشكلة للأمام (forward fix) أو تسوية البيانات بصورة واضحة. ولا يقوم النظام بأي خفض تلقائي للإصدار أو إجراء إصلاحات هدامة تلقائياً.

## التحقق وضمان الجودة

من مجلد `backend/`، نفّذ الأوامر: `go test ./...` و`go test -race ./...` و`go vet ./...` و`go mod verify`. تغطي اختبارات قاعدة البيانات إنشاء قاعدة بيانات جديدة وإعادة فتحها، وتشغيل 4 اتصالات فعلية، والتحقق من القيود والمؤشرات الموجهة للمالك الخطأ، وحماية مراجع الوسائط، وسجل مراجعات الإعدادات، وترتيب المجموعات، وكاتبين متزامنين، وحدود جلسة الاسترداد، وإضافة الترحيلات وإعادة تشغيلها والتحقق من بصماتها والفجوات والمخططات الأحدث والتراجع، والتعامل مع الملفات غير الآمنة. تعتمد بيانات الاختبار على مجلدات مؤقتة فقط. وتقوم بيئة التكامل المستمر (CI) أيضاً بتشغيل خادم Go الحقيقي وإعادة تشغيله على جذر بيانات واحد للتحقق من الجاهزية وحزم بناء المتصفح للإنتاج. تذكّر أن اختبارات قاعدة البيانات هذه لا تختبر مفاتيح المرور المادية العتادية أو إجراءات الاسترداد الرسمية.

يضيف الترحيل **0006** سجل تدقيق ومراجعات ترجمة الإعدادات الثابتة، مع إضافة علامة علنية (public flag) لكل مرجع وسائط إعدادات محفوظ. تظل صور الشعار غير المستخدمة وأغلفة البانر المعطلة خاصة بينما تمنع مراجعها التاريخية حذفها الفيزيائي من القرص. راجع [عقد الإعدادات](../../docs/api/configuration.ar.md).

يضيف الترحيل **0007** حقل `revisions.reading_minutes`، ويُحسب تلقائياً للمراجعات الجديدة. تحتفظ المراجعات التاريخية الثابتة بالقيمة `0` (غير معروف)؛ ويحذف استكشاف المحتوى هذا التقدير للمحتوى غير المعروف أو المقفل بمتطلبات. لا يتم تعديل أي ملف Markdown سابق. راجع [الصفحات العامة](../../docs/public-pages.ar.md).

راجع [واجهة التعلّم](../../docs/api/learning.ar.md) لمعرفة حدود الاحتفاظ بالبيانات واستخدام الأمر `build/blog cleanup-learning`. لا يقوم أي من الترحيلات ببذر بيانات للمتعلمين أو تخزين متون Markdown داخل قاعدة البيانات.

يضيف الترحيل **0010** إمكانية إتمام التعلم الدائم بصورة مستقلة عن المحاولات المحفوظة؛ بينما يضيف الترحيل **0011** تحديد نطاق ملكية الوسائط للناشر وتصريحاً صريحاً للمقالات. تُحفظ البيانات الموجودة دون مساس؛ ولا يقوم أي منهما ببذر بيانات اعتماد. تبدأ الترحيلات الجديدة من الرقم 0012.

## 0012 — التحويل الصريح لنوع المحتوى

يحافظ الترحيل الإضافي **0012** على كافة العناصر والإصدارات ومؤشرات المراجعات الموجودة. ويضيف ضوابط حماية لتحويل المعاملات، وأحداث تدقيق للأنواع، ومسارات بديلة (aliases) لعناوين URL العامة السابقة. تظل عمليات التحديث العادية للنوع أو اللغة المصدر وتغييرات العضوية المنشورة محظورة. وتختص خدمة تحويل المحتوى الخاصة بالمالك وحدها بفصل العنصر غير المخطط وتغيير نوعه داخل معاملة ذرية واحدة؛ بينما تظل العناصر المنتمية لخطط فعالة أو مسودة محمية تماماً. اتبع إجراءات النسخ الاحتياطي وبدء التشغيل الموضحة أعلاه.

## 0013 — إزالة المجموعات

يضيف الترحيل **0013** علامة حذف محفوظة تمنع إعادة تفعيل المجموعة المحذوفة أو إضافة أي عناصر جديدة إليها. وتقوم عملية الحذف الخاصة بالمالك بفصل المستندات، وتحويل الدروس إلى مقالات غير منشورة مع الاحتفاظ بالخطط والمراجعات الثابتة دون حذف. وتتطلب هذه العملية مطابقة إصدار المجموعة الحالي. خذ نسخة احتياطية قبل الترقية؛ وتظل مفاتيح المجموعات المحذوفة محجوزة لمنع تكرارها.

## 0014 — مصادقة MCP عبر OAuth

يضيف الترحيل **0014** جداول عملاء OAuth المحددة، وطلبات الموافقة والرموز، والمنح، وبصمات رموز التحديث المستهلكة بنطاقات مقيدة. لا يتم بذر أي بيانات اعتماد أو صلاحيات مسبقة. ترتبط المنح برموز الناشر المقيدة الحالية وتُحذف تلقائياً عند حذف تلك الرموز. وتؤدي عملية الاستعادة إلى مسح كافة سجلات OAuth لأسباب أمنية. احرص على أخذ نسخة احتياطية واختبار استعادة معزولة باستخدام الملف التنفيذي القديم قبل تطبيق هذا المخطط بالنسخة المرشحة، واستخدم اللقطة السابقة المطابقة في حال الرغبة بالتراجع. راجع [عمليات تكامل OAuth](../../docs/integrations/mcp-oauth.md).
