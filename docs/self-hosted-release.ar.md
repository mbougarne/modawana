# إصدارات الاستضافة الذاتية وكتالوج الإضافات

[English](self-hosted-release.md) · [التوثيق](README.ar.md)

## حزم التشغيل الأصلية

ابنِ إصدار MIT من نسخة عمل نظيفة للمصدر المرقّم. استخدم نسختَي Go وNode
المحددتين في المستودع ونسخة npm المذكورة في [دليل النشر](deployment.ar.md).
استخدم نظام التشغيل والمعمارية وبيئة البناء نفسها عند المقارنة.

```sh
node scripts/project.mjs install
node scripts/project.mjs check
node scripts/project.mjs build
go -C backend mod download all
node scripts/release/notices.mjs
node scripts/release/package.mjs vX.Y.Z
node scripts/release/check-reproducible.mjs vX.Y.Z
```

انشر الأرشيف وملف `.sha256` معاً. قارِن بصمة SHA-256 بالقيمة التي حصلت
عليها من قناة الإصدار الموثوقة قبل فك الضغط. نفّذ
`sha256sum -c vX.Y.Z.tar.gz.sha256` بجانب الأرشيف في Linux، أو
`shasum -a 256 -c vX.Y.Z.tar.gz.sha256` في macOS. يسجّل `release.json`
معرّف مراجعة المصدر، ووجود تغييرات محلية، والمنصة، والأدوات، وبصمات الملفات.
يتيح ثبات ترتيب الملفات وأذوناتها وتوقيتها وملكيتها إعادة إنشاء الأرشيف بنفس
البايتات عند تطابق مدخلات البناء. للتحقق من بناء مستقل، أعد تنفيذ الأوامر من
نسخة عمل نظيفة ثانية للمراجعة نفسها وقارِن بصمة الأرشيف. انشر بناءً من مصدر
نظيف مع وسم المراجعة المطابقة.

يمكن للمشرفين تشغيل إجراء **Self-hosted release candidate** من الفرع `main`
في GitHub Actions. أدخل رقم الإصدار المقصود، مثل `v0.1.0-rc.1`. يستخرج
الإجراء المراجعة المحددة في مجلدين منفصلين، ويبني حزمتي Linux x86-64، ويقارن
بايتاتهما، ويختبر الخادم المعبّأ والتثبيت من الكتالوج الموقّع. نزّل الأرشيف
المتحقق منه وملف البصمة من مخرجات التشغيل. استخدم مراجعة المصدر المثبّتة في
التشغيل لوسم الإصدار بعد إتمام مراجعة النشر. يوقّع المشرفون الكتالوج بمفتاح
الإنتاج وينشرون الإصدار في خطوتين مستقلتين.

فك الأرشيف في مجلد إصدار مستقل واضبط البيئة الخاصة كما في [دليل النشر](deployment.ar.md).
اضبط `BLOG_FRONTEND_DIST` على مجلد `frontend` المستخرج، و`BLOG_DATA_ROOT`
على مجلد بيانات خاص ودائم ومنفصل. شغّل ملف `blog` المستخرج. في التثبيت
الجديد، نفّذ `blog bootstrap` بالإعدادات نفسها وأكمل تسجيل المالك. للترقية،
أنشئ نسخة احتياطية بالملف التنفيذي القديم وتحقق منها، ثم أوقفه وشغّل الإصدار
الجديد من مجلده مع مجلد البيانات نفسه. تحقق من `blog ready`، ودخول المالك،
والمحتوى والوسائط والإضافات المفعّلة. عند وجود ترحيل غير متوافق، استعد نسخة ما
قبل الترقية في مجلد جديد بالملف التنفيذي القديم وفق
[دليل الاستعادة](operations/recovery.md).
راجع [جاهزية الإصدار](release-readiness.ar.md) قبل النشر العام.

| المكوّن | التوافق |
| --- | --- |
| الأرشيف الأصلي | طابق نظام التشغيل والمعمارية في `release.json`. يُختبر Linux x86-64 في التكامل المستمر. |
| بيئة التشغيل | ملفات Go التنفيذية وملفات Webpack وSQLite محلية وملفات ثابتة. يُستخدم Node للبناء أو نشر الكتالوج. |
| الوحدات الرسمية | النشر الاجتماعي والإحصاءات والمساعد التحريري والمتجر وPayPal مضمّنة. تحتاج الخدمات الاختيارية إلى بيانات اعتماد التثبيت. |
| إضافات WASI | مخطط بيان الإضافة 1 وواجهات المضيف من 1 إلى 5. تضم الحزمة مثالاً مبنياً ومثالاً بمصدر TypeScript. |
| القوالب | واجهة الحزم العامة 1 (أجزاء المضيف وCSS مقيّد النطاق) و2 (تخطيطات ورموز المضيف). تضم الحزمة مثالاً للإصدار 2. |
| الكتالوج | مخطط الفهرس 1 وتوقيع Ed25519 منفصل وبصمات SHA-256 للحزم. يتوفر أيضاً الاعتماد المحلي بالبصمة. |

## نشر الكتالوج المنتقى

يضم الإصدار ملف `examples/catalog-spec.json` للإضافة والقالب النموذجيين
الرسميين. أدرج الإضافات التي خضعت للمراجعة وأصدر رقماً جديداً عند تغيير
بايتات الحزمة. حزمة الإضافة هي ZIP لملفات عادية، منها `manifest.json`
ووحدة WASM في جذر الأرشيف. حزمة القالب هي ملف `theme.json` الأصلي.
من مجلد الإصدار المستخرج، جهّز الحزمة ووقّع الفهرس بمفتاح Ed25519 غير متصل.
اختر موعد انتهاء مستقبلياً بتوقيت UTC.

```sh
(cd examples/plugins/example && zip -X ../../plugin-example.zip manifest.json plugin.wasm)
node scripts/release/catalog.mjs index examples/catalog-spec.json catalog.json "$CATALOG_EXPIRY"
node scripts/release/catalog.mjs sign catalog.json /private/catalog-signing.pem release-1 catalog.sig.json
node scripts/release/catalog.mjs keyring /private/catalog-public.pem release-1 trusted-keys.json
```

انشر الفهرس وتوقيعه المنفصل وجميع الحزم المشار إليها. وزّع المفتاح العام عبر
قناة موثوقة مستقلة. طابق بصمته مع القيمة الموثّقة من الناشر قبل إضافته إلى
قائمة الثقة المحلية. احتفظ بمفتاح التوقيع خارج Git ومن دون اتصال. تقبل قائمة
الثقة عدة معرّفات للمفاتيح. للتدوير، وثّق المفتاح العام الجديد وأضفه إلى
`keys` وانشر توقيعاً بمعرّفه. لإلغاء مفتاح، أضف معرّفه إلى `revoked`
واحذفه من `keys`. يُرفض المعرّف الملغى حتى إن بقي مفتاحه موجوداً.
استبدل نسخ الكتالوج المخزّنة وراجع الإصدارات المثبّتة مسبقاً بواسطة ذلك المفتاح.
يؤثر الإلغاء في عمليات التحقق اللاحقة. عطّل الإضافات المتأثرة من لوحة التحكم
أو اختر قالباً آخر.

## المعاينة والاعتماد والاستعادة

احفظ الكتالوج والتوقيع وقائمة الثقة والحزمة المطابقة محلياً. أنشئ نسخة
احتياطية قبل ترقية إضافة. أوقف الخدمة واستخدم مستخدم التشغيل المعتاد
وبيئته ومجلد `BLOG_DATA_ROOT` نفسه.

```sh
./blog extension preview --catalog catalog.json --signature catalog.sig.json \
  --keyring trusted-keys.json --bundle examples/plugin-example.zip \
  --kind plugin --id example --version 0.1.0
./blog extension install --catalog catalog.json --signature catalog.sig.json \
  --keyring trusted-keys.json --bundle examples/plugin-example.zip \
  --kind plugin --id example --version 0.1.0 --approve "$REVIEW_SHA256"
```

راجع البيانين السابق والمقترح، وخصوصاً الصلاحيات والمسارات ومضيفي HTTPS
والترحيلات. يعدّ `applied_migrations` الترحيلات المنفّذة سابقاً في بداية
قائمة المرشح. اضبط `REVIEW_SHA256` على قيمة `review_sha256` المعروضة بعد
المراجعة. يعيد أمر التثبيت التحقق من الثقة والفهرس والحزمة ويربط الاعتماد
بمراجعة التثبيت نفسها. للقالب استخدم `--kind theme --id pack-example
--version 1.0.0 --bundle examples/themes/pack-example/theme.json`.
احتفظ بمخرجات التثبيت في سجلات الإصدارات الخاصة لتتمكن من ربط الحزم
المثبّتة بمفتاح توقيعها عند إلغائه.

تبقى الإضافة المعتمدة لأول مرة معطلة حتى تفعيلها من لوحة التحكم. تُنفّذ
الترحيلات المعلقة في معاملة اعتماد ترقية إضافة مفعّلة. عند رفض حزمة أو
معاينة قديمة أو فشل ترحيل يبقى الإصدار المعتمد وبياناته سليمة. تحفظ الإصدارات
المعتمدة في مجلدات معنونة ببصماتها ويعاد التحقق منها عند التشغيل. شغّل الخدمة
لاستخدام الإصدار المعتمد، واختر القالب الجديد من لوحة التحكم. لتثبيت إضافة
أو قالب محلي، استخدم الاعتماد بالبصمة من لوحة التحكم كما هو موضح في
[الإضافات](plugins.ar.md) و[أدوات المالك](owner-tools.ar.md).

عطّل الإضافة من لوحة **الإضافات** لإيقاف مساراتها ومهامها مع إبقاء بياناتها.
صدّر بيانات الإضافات بأمر `blog backup --file /absolute/pre-upgrade.zip`.
تضم النسخة الملفات المعتمدة المطابقة وبيانات الإضافات وإعداداتها واعتماد
القوالب. احفظها مشفّرة. تُضبط أسرار الإضافات مجدداً بشكل منفصل. للاستعادة بعد
ترحيل منفّذ، استعد نسخة ما قبل الترقية في مجلد بيانات جديد بإصدار مدوّنة
المطابق واتّبع [خطوات إعادة التسجيل والاستئناف](operations/recovery.md).
