# بيئة التطوير المحلي

[English](getting-started.md) · [التوثيق](README.ar.md)

تأكد من استخدام الإصدارات المثبتة في ملفات `.node-version` و`frontend/package.json` و`backend/go.mod`. تُنفذ كافة أوامر السكربت `scripts/project.mjs` من المجلد الجذري للمستودع دائماً. يقوم الأمر `install` بتشغيل `npm ci` داخل مجلد `frontend`، بينما يتولى Go جلب وحل تبعيات الوحدات تلقائياً عند البناء أو إجراء الاختبارات.

```sh
node scripts/project.mjs install
export BLOG_DATA_ROOT="$HOME/.local/share/personal-blog-dev"
node scripts/project.mjs dev
```

يستمع خادم تطوير Webpack على المنفذ `127.0.0.1:3000` ويعيد توجيه طلبات API والوسائط تلقائياً إلى خادم Go على `127.0.0.1:8082`. افتح في المتصفح `http://localhost:3000/ar` أو `/en` أو `/fr`. لإيقاف كلا خادمي التطوير، اضغط على `Ctrl+C`. احرص على أن يكون مسار مجلد البيانات الموضح في المتغير `BLOG_DATA_ROOT` مساراً مطلقاً، ومحمياً بصلاحيات خاصة، وخارج شجرة المستودع تماماً. وفي حال عدم تعيين المتغير `BLOG_DATA_ROOT`، سيستخدم المشغل مجلداً مؤقتاً خاصاً بالمستودع قد يقوم نظام التشغيل بمسح محتوياته دورياً. استخدم مسار مجلد البيانات نفسه في كافة نوافذ الطرفية المفتوحة.

## تهيئة حساب المالك الأول

في نافذة طرفية ثانية، شغّل الأمر: `node scripts/project.mjs bootstrap`. سيطبع لك تصريح إعداد (grant) صالحاً للاستخدام مرة واحدة فقط ولمدة عشر دقائق؛ أدخل هذا التصريح في نموذج الإعداد الأولي/الاسترداد المحلي بصفحة تسجيل الدخول مع عنوان بريدك الإلكتروني الخاص. سجّل مفتاح مرور جديداً (passkey) ثم سجّل دخولك باستخدامه. لا يحتوي التطبيق على أي حساب مالك أو محتوى تجريبي مُعد مسبقاً. وإذا كان هناك مالك مسجل بالفعل، فعليه تسجيل الدخول مباشرة أو استخدام إجراءات الاسترداد؛ فالأمر bootstrap لا يستبدل حساباً موجوداً مسبقاً.

يدعم متصفح Chromium تجربة التطوير عبر بروتوكول HTTP على المضيف `localhost`؛ لكن سلوك المتصفحات الأخرى قد يختلف. احرص على توحيد اسم المضيف المستخدم دائماً، لأن `localhost` و`127.0.0.1` يمثلان أصلين مختلفين تماماً في معيار WebAuthn. وإذا تعذر على متصفحك أو مزود مفاتيحك تسجيل المفتاح عبر HTTP، فانتقل إلى إعداد اتصال HTTPS المحلي الموثوق الموضح أدناه.

لإجراء اختبارات محلية مؤتمتة في Google Chrome، افتح أدوات المطور (DevTools) ← المزيد من الأدوات (More tools) ← ثم WebAuthn. فعّل البيئة الافتراضية (Enable virtual environment)، وأضف مصادقاً داخلياً (internal authenticator) يدعم بروتوكول CTAP2، والمفاتيح المقيمة (resident keys)، والتحقق من المستخدم (user verification). احرص على تفعيل التحقق والحضور التلقائي، وأبقِ نافذة DevTools مفتوحة أثناء عمليتي التسجيل والدخول. يُرجى الانتباه إلى أن هذا المصادق عامل افتراضي للمحاكاة فقط، ولا يُثبت التوافقية مع الهواتف الذكية أو المزودين السحابيين أو مفاتيح الأمان المادية الحقيقية.

## اتصال HTTPS محلي موثوق

أوقف بيئة تطوير HTTP أولاً. بعد تثبيت أداة `mkcert`، أنشئ شهادة localhost موثوقة في مسار خارج مجلد Git. قد يتطلب تثبيت المرجع المصدق المحلي (Local CA) الحصول على صلاحيات مدير النظام:

```sh
mkdir -p /tmp/personal-blog-local-tls
chmod 700 /tmp/personal-blog-local-tls
mkcert -install
mkcert -cert-file /tmp/personal-blog-local-tls/cert.pem -key-file /tmp/personal-blog-local-tls/key.pem localhost 127.0.0.1
export BLOG_DEV_TLS_CERT=/tmp/personal-blog-local-tls/cert.pem
export BLOG_DEV_TLS_KEY=/tmp/personal-blog-local-tls/key.pem
node scripts/project.mjs dev:https
```

افتح الرابط `https://localhost:3000/ar/login`، واستخدم الأمر `node scripts/project.mjs bootstrap:https` في نافذة الطرفية الثانية مع الإبقاء على جذر البيانات نفسه. يتحقق المشغل من صحة المفتاح الخاص والشهادة قبل الإقلاع؛ ولا يقوم بتثبيت مراجع مصدقة على مستوى النظام أو إضعاف قيود ملفات تعريف الارتباط الآمنة الخاصة ببيئة الإنتاج.

## استكشاف الأخطاء الشائعة وإجراءات الاسترداد

- **فقدان عامل مصادقة التطوير، أو إنشاء الحساب دون إتمام تسجيل المفتاح**: شغّل الأمر `node scripts/project.mjs recover` (أو `recover:https` في حال استخدام HTTPS)، ثم حدّث صفحة تسجيل الدخول وأدخل التصريح الجديد مع استخدام **البريد الإلكتروني نفسه**. يقوم الاسترداد بإلغاء الجلسات النشطة وتدفقات المصادقة المعلقة مع الحفاظ الكامل على كافة المحتويات. بعد ذلك، سجّل عامل مصادقة بديلاً واختبره فوراً.
- **انتهاء صلاحية تصريح الإعداد**: تنتهي صلاحية التصريح بعد 10 دقائق وهو صالح للاستخدام مرة واحدة فقط. احرص على عدم تضمينه في الروابط، أو ملفات السجلات، أو لقطات الشاشة، أو رسائل المحادثة، أو معاملات أوامر الطرفية.
- **تغيير معرف الطرف المعتمد (RP ID) أو النطاق**: يؤدي تغيير RP ID أو النطاق إلى عدم تطابق مفاتيح المرور المسجلة سابقاً وعدم إمكانية نقلها. اتبع [إجراءات الاسترداد الموثقة](owner-security.ar.md) ولا تعمد أبداً إلى تخفيف قيود الأصول المسموحة (allowed origins).
- **المنفذ قيد الاستخدام بالفعل**: أوقف عملية التطوير السابقة التي تشغل المنفذ. يمكنك تعيين عنوان ومنفذ مختلفين للخلفية عبر المتغير `BLOG_LISTEN_ADDR` وسيقوم وكيل التطوير باتباعه تلقائياً.

للنشر في بيئة الإنتاج الفعلية، اتبع [دليل النشر](deployment.ar.md). تذكّر دائماً أن شهادات TLS المحلية والمصادقات الافتراضية هي مجرد أدوات اختبار تشخيصية وليست بديلاً عن إعدادات الأمان الإنتاجية الحقيقية.
