# تهيئة المالك والأمان

[English](owner-security.md) · [API](api/README.ar.md) · [مفاتيح المرور والأجهزة](passkey-access.ar.md)

يدعم التطبيق مالكاً واحداً ودخولاً بمفتاح المرور أولاً وكلمة مرور مع TOTP اختيارية
واسترداداً مقيداً. لا تُزرع هوية أو عوامل. الصفحات `/{en|ar|fr}/login` و`/{en|ar|fr}/admin/security`. يُعاد
تنقل المتصفح الذي يطلب HTML صراحة إلى صفحة إدارة بلغة مدعومة دون جلسة مالك صالحة
إلى صفحة دخول اللغة نفسها، مع حفظ وجهة عودة محلية متحقق منها. يُعد `/admin/login`
و`/{locale}/admin/login` اسمين بديلين للمتصفح لمسار الدخول الفعلي. تستمر طلبات API
والطلبات التي لا تطلب HTML بإرجاع أخطاء JSON برمز 401. تعود شاشات الإدارة
المفتوحة إلى الدخول عند 401 غير معالَجة بتجديد ناجح؛ ولا تسبب أخطاء 403 الخاصة
بالصلاحيات أو حداثة الدخول إعادة توجيه بمفردها. يبقى تجديد مفتاح المرور والدخول
بكلمة مرور مع TOTP متاحين. يُتعرف أيضاً على مسار النقل في المتصفح.
تتطلب مصادقة الإنتاج HTTPS على الأصل المضبوط.
لاختبار Chrome محلياً دون شهادات، يستخدم `node scripts/project.mjs dev` العنوان
`http://localhost:3000` وRP ID بقيمة `localhost`؛ يدعم Chrome ملفات Secure وWebAuthn
على localhost. قد يحتاج Safari إلى HTTPS موثوق. راجع
[دليل الاختبار المحلي](../README.ar.md#اختبار-دخول-المالك-والكتابة-محلياً)، بما فيه
خيار المصادق الافتراضي المدمج. لا تثبت المحاكاة توافق مفاتيح المرور الفعلية.
لا تضعف ملفات الارتباط أو فحوص أصل الإنتاج.

## التهيئة المحلية

اضبط بيئة دليل API وابن التطبيق وانسخ البيانات الموجودة قبل الترحيل. نفذ على VPS
بمستخدم نظام التشغيل الخاص بالخدمة:

```sh
./build/blog bootstrap
```

يطبع تصريحاً عشوائياً واحداً في طرفية المشغل صالحاً لعشر دقائق. لا تضع قيمته في
وسيط أمر أو URL أو سجل أو Git. افتح صفحة الدخول واختر التصريح المحلي وأدخل
التصريح وبريد الدخول الخاص وسجل مفتاحاً مسمى. التصريح أحادي الاستخدام؛ لا مسار
تسجيل عاماً. تستمر جلسة التسجيل خمس دقائق ولا تصل إلى API المالك. ادخل بالمفتاح
المسجل لتجربته وفتح الأمان. إن تُرك الإعداد بعد إنشاء المالك فاستخدم الاسترداد المحلي.
للتطوير يستخدم `node scripts/project.mjs recover` بيئة `dev` وجذر بياناته نفسيهما؛
استخدم `recover:https` مع `dev:https`. استعمل التصريح الجديد مع بريد المالك الأصلي.
يبطل الاسترداد الجلسات والتدفقات المعلقة ويحفظ المحتوى، ويظل تسجيل مفتاح بديل
واختباره مطلوبين.

أضف احتياطاً مستقلاً وجرّبه بدخول جديد وولّد رموزاً خارج الأجهزة قبل استخدام
الإنتاج. يختار المتصفح والمزود عبر WebAuthn الأصلي: لا QR مخصص ولا تقييد بمصادق
المنصة ولا ضمان لمزامنة بين المزودين. يتطلب التسجيل والدخول UV ومفتاحاً قابلاً
للاكتشاف. الأسماء لا تثبت الاستقلال. يحفظ الخادم بيانات المفتاح العام والعداد
والنسخ الاحتياطي دون المفتاح الخاص. الحد 20 مفتاحاً نشطاً. الإلغاء يتطلب مفتاحاً
آخر مجرّباً أو بديل TOTP مسجلاً؛ لا يبرر البديل غير المجرّب حذف آخر مفتاح صالح.
يلغي إلغاء المفتاح جلسات المالك بما فيها الجلسة الحالية. لا يعد إعداد TOTP ذا بذرة غير متاحة أو متعذرة الفك بديلاً صالحاً لآخر مفتاح مرور.

## كلمة المرور وTOTP الاختياريان

لتفعيل البديل جهز مفتاح تشفير ثنائياً منفصلاً من 32 بايت خارج `BLOG_DATA_ROOT`
والمستودع ومجلدات الإصدار. يصلح مجلد أسرار مشغل محمي. مثال بعد إنشاء ذلك المجلد
الخاص بحساب الخدمة:

```sh
umask 077
openssl rand -out /srv/personal-blog-secrets/auth.key 32
export BLOG_AUTH_KEY_FILE=/srv/personal-blog-secrets/auth.key
```

لا تستبدل مفتاحاً موجوداً. يجب أن يكون الملف عادياً وخاصاً (0600 أو أشد) وليس
رابطاً رمزياً وخارج جذر البيانات الفعلي. انسخه في حزمة استرداد محمية منفصلة؛ فقده
يعطل بذور TOTP الحالية. لا يولد التطبيق مفتاحاً خفية. بدونه لا يتوفر تسجيل TOTP،
وتظل مفاتيح المرور والاسترداد المحلي والرموز في وضع المفاتيح تعمل.

أدخل في الأمان كلمة جديدة من 12 محرفاً على الأقل وبحد 1024 بايت UTF-8. أضف السر
المعروض إلى تطبيق المصادقة بستة أرقام وSHA-1 وفترات 30 ثانية ثم تحقق من رمز.
يُعرض السر أثناء التسجيل فقط؛ تحفظ SQLite تشفير AES-GCM مرتبطاً بالمالك، بما فيه
البذور المعلقة. يفعّل التحقق البديل ويلغي الجلسات. تستبدل البذرة الجديدة القديمة
بعد التحقق فقط؛ يحفظ فشل الإعداد القديمة.

تستخدم كلمات المرور Argon2id v19 مع salt و64 MiB وثلاث دورات ومسارين ونتيجة
32 بايت وsalt من 16 بايت. تُحد العمليات المتزامنة لاشتقاق كلمات المرور باثنتين
لكل عملية Go لضبط الذاكرة. بلغ القياس المحلي على Apple M3 Pro نحو 59 ms؛ نفذ
`go test ./internal/auth -bench BenchmarkArgon2id -benchtime=3x` داخل `backend/`
على VPS الفعلي قبل الإنتاج؛ ليس هذا ادعاءً بأداء VPS. نجاح كلمة المرور يعطي
تحدياً معلقاً لخمس دقائق فقط. يقبل TOTP انحراف فترة واحدة قبل الوقت وبعده ويرفض
ذرياً كل فترة قُبلت سابقاً بما فيها رمز التسجيل. اضبط ساعة VPS. يتطلب تعطيل
البديل مفتاحاً مجرّباً ويلغي الجلسات.

## الرموز والاسترداد المحلي

تولد صفحة الأمان عشرة رموز مستقلة أحادية الاستخدام من 256 بت، تعرض مرة واحدة
وتحفظ بصمات SHA-256. يبطل التجديد كل الرموز السابقة. احفظها خارج الأجهزة قبل
المغادرة؛ لا يستطيع الخادم عرضها ثانية.

- مع تفعيل كلمة المرور وTOTP، تحقق من كلمة المرور أولاً؛ يستبدل الرمز العامل
  الثاني ولا يتجاوز كلمة المرور.
- في وضع مفاتيح المرور فقط، يعطي الرمز تسجيل عامل لخمس دقائق فقط. تُلغى الجلسات
  والتحديات؛ لا يتيح تصريح الاسترداد النشر.
- عند فقد العوامل والرموز نفذ `./build/blog recover` محلياً. يلغي الجلسات والتحديات
  ويصدر تصريحاً أحادياً لعشر دقائق. استرده ببريد الدخول الخاص الحالي في النموذج
  نفسه. لا مسار عاماً لتعطيل MFA. بعد تسجيل البديل ادخل به لتجربته؛ عندها فقط
  تلغى العوامل القديمة والرموز المتبقية. ولّد رموزاً جديدة فوراً.
- التسجيل وحده لا يحوّل الاسترداد إلى جلسة كاملة؛ يلزم إثبات لاحق بالمفتاح الجديد.
  لا يستطيع التطبيق إصلاح فقد الوصول إلى VPS مع جميع العوامل والرموز. حافظ على
  وسائل مستقلة لاسترداد حساب VPS والمزود. سجلات المفتاح العام لا تستعيد الخاص.
  راجع سجل الأمان بعد الاسترداد.

## الجلسات وCSRF والتدقيق

يستخدم `__Host-owner` و`__Host-auth` خصائص Secure وHttpOnly وSameSite=Strict
وPath=/ دون Domain. تحفظ SQLite بصمات أسرار الارتباط والتصريح والرمز فقط.
للجلسات حد خمول ساعتين وحد مطلق 12 ساعة وتُدوّر بعد المصادقة الكاملة. التدفقات
المقيدة سجلات منفصلة لا جلسات مالك. التغييرات الحساسة تتطلب مصادقة كاملة خلال
30 دقيقة؛ جددها بدخول بمفتاح أو بكلمة المرور والعامل الثاني. لا اختصار ثقة جهاز
ولا JWT أو رمز ناشر في تخزين المتصفح.

يتطلب `POST /api/v1/auth/start` الأصل المطابق و`X-Blog-Request: 1` لإنشاء ارتباط
ما قبل الدخول وقيمة CSRF، دون سماح CORS. تتطلب كل كتابة لاحقة الأصل المطابق
و`X-CSRF-Token` بما فيها الدخول والخروج والتسجيل والعوامل والاسترداد. يعيد
`GET /session` الحالة وCSRF دون أسرار الارتباط ولا ينشئ تصريحاً. ترفض الحالة
المنتهية أو الملغاة.

تشترك المحاولات الفاشلة في عدادات IP والحساب بين التحديات: خمس إخفاقات لكل IP
عميل موثوق أو 25 للحساب الوحيد تفرض توقفاً محدوداً 15 دقيقة. لمسارات البدء
والخيارات والتصاريح سقوف محاولات أيضاً. تحفظ SQLite الحدود بعد إعادة التشغيل؛
لا تقبل العناوين المحولة إلا عبر الوكلاء الموثوقين المضبوطين. الأخطاء عامة.
يحفظ التدقيق آخر 1000 اسم حدث آمن ومعرّف طلب مولد وتوقيت UTC. لا تسجل بيانات
اعتماد أو بذوراً أو OTP أو رموزاً أو أسراراً خاماً أو البريد الخاص. طبّق ذلك في الوكيل العكسي.

## التحقق وفحوص العتاد المتبقية

تفحص `go test ./...` و`go test -race ./...` وفحوص الواجهة والبناء حدود التخزين
والأمان. يستخدم `node scripts/smoke-auth.mjs` بناء Go وSQLite حقيقية ووكيل HTTPS
مؤقتاً ومصادقات Chromium افتراضية. يفحص التهيئة ومفتاحين والاسترداد بالرمز في وضع
المفاتيح وكلمة المرور وTOTP الاختياريين والاسترداد المحلي والخروج ورفض CSRF وطلب
الإدارة المباشر باللغات الثلاث بعرض الهاتف. هويات ومفاتيح وبيانات الاختبار مؤقتة
لا بيانات إنتاج. لا تشمل الصور قيم البذور والرموز. نفذه بعد البناء المعتاد
و`npm --prefix frontend test` وتثبيت Chromium لـ Playwright.

**التحقق من العتاد:** لا تثبت الاختبارات الافتراضية QR الهاتف أو قرب Bluetooth أو مزامنة المزود
أو التوافق الحقيقي. قبل الاستخدام الإنتاجي سجّل نظام التشغيل والمتصفح والمزود
وطراز المفتاح ونتائج: حاسوب جديد دون مفتاح محلي؛ الدخول بالهاتف؛ مفتاح فعلي مستقل
مع UV؛ الإلغاء وعدم الدعم؛ فقد مفتاح؛ الاسترداد المحلي وبالرمز. تغيير RP ID أو
النطاق يتطلب خطة تسجيل واسترداد ولا يبرر توسيع الأصول خفية.
