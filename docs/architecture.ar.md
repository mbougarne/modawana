# البنية المعمارية (Architecture)

[English](architecture.md) · [التوثيق](README.ar.md)

تطبيق **مدوّنة** منصة نشر ذاتية الاستضافة مخصصة لمالك واحد. تتولى عملية تشغيلية واحدة مكتوبة بلغة Go خدمة ملفات React المترجمة وتوفير واجهة البرمجة (API) من أصل النطاق (origin) نفسه، وذلك خلف خادم وكيل عكسي يدعم اتصالات HTTPS. تتولى قاعدة بيانات SQLite إدارة البيانات الوصفية وحالة النظام؛ بينما تُخزن متون Markdown والوسائط المرفوعة كملفات على وحدة تخزين محلية دائمة. لا يتطلب النظام بيئة تشغيل Node في الإنتاج، ولا يتيح التسجيل العام، ولا يعتمد على قواعد بيانات خارجية، ولا يفتح واجهات برمجة للمتصفح عبر نطاقات متباينة (cross-origin).

| المكون | المسؤولية |
| --- | --- |
| `backend/cmd/blog` | خادم HTTP، وأوامر الإعداد الأولي (bootstrap)، والصيانة، والنسخ الاحتياطي والاستعادة |
| `backend/cmd/publisher` | واجهة سطر الأوامر (CLI) للنشر محدد الصلاحيات، والتوصيل المتين، ومجدول الدروس الاختياري |
| `backend/internal` | المصادقة والتفويض، وإدارة المحتوى والوسائط، والإعدادات، والاختبارات التقييمية، والتخزين |
| `backend/migrations` | ترحيلات SQLite مرتبة ومتحقق منها ببصمات رقمية |
| `frontend/src` | مسارات React، ولوحة تحكم المالك، وقارئ الواجهة العامة، وعميل API، وعرض Markdown الآمن |
| `ui/src` | المكونات المشتركة، وتسميات اللغات (EN/AR/FR)، ومزودات السياق، والخطوط، والرموز المولدة |
| `design-system` | رموز التصميم المرجعية الأساسية، وأدوات التوليد، وملف أنماط المكونات المشترك |
| `deploy` | نماذج إعدادات Docker وCompose والوكيل العكسي وخدمات systemd |
| `scripts` | أدوات التطوير، وضمان الجودة، والنشر، والنسخ الاحتياطي، وحزم الإصدارات |

## التخزين والنشر

يختص تطبيق Go وحده بالوصول المباشر إلى قاعدة البيانات والملفات المدارة. تعتمد SQLite على قيود المفاتيح الأجنبية، ونمط WAL لتسجيل المعاملات، ومهلات انتظار محدودة للعمليات المنشغلة، ومعاملات كتابة قصيرة الأجل. يجب تشغيل مثيل واحد فقط من التطبيق على نظام ملفات محلي؛ حيث إن أنظمة الملفات الشبكية والتكرار الأفقي (horizontal replicas) غير مدعومة. ويمنع عقد الإيجار التشغيلي (runtime lease) تشغيل خادمين على جذر البيانات نفسه في الوقت ذاته.

تُنشئ كل عملية حفظ مراجعة Markdown ثابتة وغير قابلة للتعديل. وتسجل قاعدة البيانات مسارها النسبي، وبصمة تجزئتها، ومعرف المراجعة الأصلية السابقة. وتختار عملية النشر مراجعة محفوظة بعينها بدقة؛ فلا يؤدي تعديل مسودة لاحقة إلى تغيير النسخة المنشورة حياً. تمنع آليات التحقق التفاؤلي للإصدارات (optimistic versions) تعارض التعديلات المتزامنة، بينما تضمن مفاتيح العمليات عديمة الأثر (idempotency keys) إمكانية إعادة إرسال الطلبات المتطابقة دون تكرار إنشاء المراجعات. وتُعد ملفات الترحيل تراكمية ومحمية ببصمات SHA-256.

تُنشر ترجمات المحتوى بصورة مستقلة لكل لغة بعد مراجعتها وتدقيقها مقابل مراجعة النص المصدر. وعند عدم توفر ترجمة معينة للمحتوى، يوفر قارئ الموقع خيارات تنقل لغوي واضحة وصريحة دون اللجوء إلى استبدال متن المحتوى بلغة أخرى بصورة صامتة. أما نصوص الملف التعريفي العام وتسميات الواجهة فلها قواعد بديلة موثقة وواضحة.

## حدود الوصول والتفويض

يتطلب وصول المالك تسجيل الدخول بمفتاح مرور (passkey) أو بكلمة مرور مدعومة برمز TOTP. وتتيح إجراءات الاسترداد إعادة تسجيل عوامل المصادقة بنطاق مقيد، مع اشتراط تسجيل دخول ناجح بالعامل البديل الجديد لاستئناف العمليات. وتتمتع رموز الناشر البرمجية بصلاحيات مستقلة ومفصلة للمسودات، والوسائط، والاختبارات، والنشر، بالإضافة إلى حدود مخصصة للمجموعات. كما ترث تصاريح تكامل OAuth حدود الرمز الأب المرتبطة به ويمكن إلغاؤها بشكل مستقل.

تظل الدروس المنشورة والمشروطة بمتطلبات مسبقة (gated lessons) خاضعة للتحقق من استيفاء المتطلبات في جانب الخادم. وتحمي السياسة الأمنية نفسها متون الدروس، والوسائط، والبيانات الوصفية، والظهور في الاستكشاف والبحث، والمعاينات، والخلاصات، وبطاقات المشاركة الاجتماعية. وتذكر دائماً أن إخفاء المحتوى عبر CSS لا يُعد بأي حال وسيلة للتحكم في الوصول. وتكون هويات التعلّم المرتبطة بالمتصفح مستقلة تماماً عن جلسات المالك. وتتم عمليات تصحيح الاختبارات التقييمية وتحديث تقدم التعلّم داخل معاملات ذرية آمنة؛ مع حجب مفاتيح الإجابات تماماً عن استجابات الأسئلة الموجهة للقارئ.

تُعرض نصوص Markdown عبر مسار برمجي آمن وموحد في الواجهة الأمامية للمعاينات والقراءة العامة. ولا يدعم النظام تضمين كود HTML الخام، أو ملفات MDX التنفيذية، أو السكربتات العشوائية، أو التضمينات الخارجية غير المنضبطة. وتستبعد سجلات النظام كافة الأسرار، وسلاسل الاستعلام (query strings)، ومتون المسودات غير المنشورة. وتعتمد عمليات الكتابة من المتصفح على قيود الأصل نفسه وفحوصات الحماية من تزوير الطلبات عبر المواقع (CSRF)؛ بينما يعتمد النشر الآلي على مصادقة الرموز الحاملة (bearer tokens) المحددة الصلاحيات.

## الإعدادات والعمليات التشغيلية

تُعامل الهوية البصرية، ومعلومات الملف الشخصي، ونصوص التسميات كإعدادات تطبيق تخضع لنظام تتبع الإصدارات. أما أصول المشغل، ومفاتيح التشفير والمصادقة، ومسارات نظام الملفات فهي إعدادات تشغيل سرية تُضبط في بيئة التشغيل، ولا تُضمّن مطلقاً كمتغيرات داخل حزم المتصفح. ويقتصر خادم الإنتاج على تقديم أصول البناء المدرجة في بيان الأصول (manifest) فقط.

تجمع النسخة الاحتياطية لقطة حية منسقة لقاعدة بيانات SQLite مع كافة الملفات المرجعية المرتبطة بها على القرص. ويؤدي إجراء الاستعادة عمداً إلى إبطال بيانات الاعتماد وتصفير تقدم التعلّم، والدخول في وضع الصيانة، واشتراط اختبار تسجيل الدخول بالعامل الجديد قبل استئناف الخدمة. ويُعد استيراد وتصدير المحتوى صيغة نقل بيانات مستقلة تُنتج مسودات فقط. راجع [دليل الاسترداد](operations/recovery.md).

يعتمد تكامل [بروتوكول MCP](integrations/mcp-oauth.md) وخاصية [توصيل الدروس](integrations/lesson-delivery.ar.md) الاختياريان على قواعد التفويض والمراجعات المعتمدة لدى خدمة الناشر نفسها. وتُعد منصة Notion وجهة مستقلة لتصدير المحتوى دون وجود مزامنة ثنائية الاتجاه تلقائية. ويجري التوليد المجدول للدروس داخل عملية الناشر باستخدام بيانات اعتماد مهيأة بشكل منفصل.

للاطلاع على العقود المفصلة، راجع [عقود الإعدادات ومسارات التعلّم](architecture-appendix-configurable-learning.ar.md)، و[مرجع API](api/README.ar.md)، و[عقود الواجهة](ui-contracts.ar.md)، و[دليل التصميم](design.ar.md).
