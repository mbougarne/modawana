# عقود بروتوكول HTTP وإعدادات التشغيل (HTTP and Configuration)

[English](README.md) · [التوثيق](../README.ar.md) · [مواصفات OpenAPI v1](v1.openapi.json)

تغطي واجهة البرمجة (API) المعتمدة على أصل النطاق نفسه (same-origin) وظائف المصادقة، والأمان، وإدارة المحتوى والوسائط، والإعدادات العامة، ومسارات التعلّم، والنشر البرمجي محدد الصلاحيات. وتظل الموارد الخاصة محمية بصلاحياتها بصرف النظر عن مسارات التوجيه في الواجهة الأمامية. احرص على إبقاء مواصفات OpenAPI وملف عقود الواجهة `frontend/src/api/contracts.ts` متوافقين ومطابقين تماماً لقواعد التحقق المنفذة في Go.

| المسار | السلوك البرمجي وضوابط الاستجابة |
| --- | --- |
| `GET/HEAD /healthz` | فحص حيوية الخدمة (Liveness)؛ يُرجع رمز 200 مع حمولة `{"status":"ok"}` |
| `GET/HEAD /readyz` | يُرجع رمز 200 عند جاهزية كافة التبعيات بفحص محدود زمنياً؛ وإلا يُرجع رمز 503 |
| `GET/HEAD /api/v1/public/runtime` | قائمة بيضاء عامة صريحة تضم: `api_version` و`default_locale` و`locales` |
| `GET/HEAD /assets/{hashed-name}` | تقديم الملفات الثابتة المسجلة حصراً في بيان أصول البناء المعتمد |
| `GET/HEAD /`, `/en`, `/ar`, `/fr` | تقديم هيكل صفحة HTML المهيأ من Go لتحميل تطبيق React، مع ضبط سمتي `lang` و`dir` بحسب اللغة |
| طلب مسار مفقود في API أو الوسائط | يُرجع استجابة JSON برمز 404 صراحة، ولا يُرجع صفحة HTML بنجاح وهمي |
| طلب صفحة ويب غير معروفة | يُرجع صفحة HTML برمز 404 مصحوبة بوسم `noindex` لمحركات البحث |

لا يُصدر الخادم أي سماحية لمشاركة الموارد عبر الأصول المختلفة (CORS). وتعتمد استدعاءات API من المتصفح على مسارات نسبية. وتستخدم كافة استجابات JSON، ورسائل الأخطاء، وصفحات HTML سياسة منع التخزين المؤقت `Cache-Control: no-store`؛ بينما تستخدم أصول البناء الناجحة سياسة تخزين مؤقت ثابتة غير قابلة للتعديل لمدة عام كامل (`immutable`). ويقوم خادم Go بخدمة حزم الإنتاج ذاتياً دون الحاجة لتشغيل بيئة Node.js. ويُولد المعرف العشوائي (nonce) لسكربت هيكل الصفحة بصورة جديدة ومستقلة مع كل استجابة؛ حيث تمنع سياسة أمان المحتوى (CSP) السكربتات الخارجية، والتضمين في إطارات (framing)، وعناصر objects، وتنسيقات الأنماط المضمنة التي لا تحمل قيمة nonce المطابقة. ويقبل مكون BrandStyle قيمة nonce الخاصة بالاستجابة الممررة عبر عنصر meta؛ ولا تحتاج لوحة الألوان الافتراضية لأي ملف تجاوز خارجي. ويجب أن تحافظ الأنماط الديناميكية المستقبلية على قيمة هذا المعرف أو تعتمد على مسار مخصص لملفات الأنماط.

## الأخطاء والتحقق من المدخلات المقيدة

تتبع رسائل الأخطاء الهيكل الموحد: `{"error":{"code":"not_found","message":"Resource not found.","request_id":"…"}}`. ويحمل حقل `fields` الاختياري أكواد تحقق آمنة ومحددة، ولا يكشف أبداً عن أي أسرار مرسلة. وتتطابق أكواد الأخطاء مع رموز حالة HTTP القياسية: 400 للطلبات المشوهة (malformed)، و401 للمصادقة المفقودة (unauthenticated)، و403 للوصول الممنوع (forbidden)، و404 للموارد المفقودة (missing)، و405 للطرق غير المسموحة (method)، و409 لتعارض المراجعات أو تكرار الطلبات (conflict)، و413 للحمولات الكبيرة (too large)، و415 لنوع المحتوى غير المدعوم (content type)، و422 لعدم مطابقة حقول البيانات (fields)، و429 لتجاوز معدل الطلبات (throttled)، و500 للأخطاء الداخلية، و503 لعدم توفر الخدمة (unavailable). وتُضيف قيود معدل محاولات المصادقة ترويسة `Retry-After`. وتكون الرسائل الموجهة للبشر عامة ومحايدة؛ بينما تربط نصوص واجهة المستخدم الأكواد بصياغات مترجمة ملائمة.

تقبل دالة `DecodeJSON` بنية برمجية محددة الأنواع مع فرض حد أقصى لحجم البايتات لكل مسار صراحة. وتشترط الدالة ترويسة `application/json`، وترفض قيم `null`، والمصفوفات، والحقول غير المعروفة، ومحارف JSON الإضافية اللاحقة، وتقيد حجم متن الطلب بدقة حتى في حال غياب ترويسة `Content-Length`. ولا توجد أي نقاط تعديل برمجية مخصصة لاختبار هذا المحلل فحسب. وتُولد معرفات الطلبات (`request_id`) في جانب الخادم حصراً، ويتم تجاهل أي معرفات واردة من العميل. وتقتصر ملفات السجلات على تدوين المعرف المولد، والعملية من القائمة المصرح بها، ورمز الحالة، ومدة التنفيذ؛ وتخلو تماماً من متون الطلبات، وملفات تعريف الارتباط، وترويسات التفويض، وعناوين URL الخام، ومعاملات الاستعلام، وقيم الإعدادات، وتفاصيل أخطاء المعالجات الداخلية. وتتطلب سجلات الخادم الوكيل العكسي تطبيق مستويات التنقيح والحماية نفسها.

## إعدادات المشغّل (Operator Configuration)

تُقرأ متغيرات الإعداد من بيئة تشغيل النظام مباشرة وليس تلقائياً من ملفات `.env`. وتقتصر رسائل الأخطاء على ذكر اسم المتغير المتعثر فقط. ولا يتم تضمين أي من متغيرات البيئة السرية داخل حزم بناء الواجهة الأمامية.

| المتغير | القاعدة والضوابط المتبعة |
| --- | --- |
| `BLOG_ENV` | تكون القيمة إما `production` (الافتراضية في الإنتاج) أو `development` (لبيئة التطوير) |
| `BLOG_BASE_URL` | أصل النطاق الدقيق دون شرطة مائلة ختامية أو مسار أو استعلام أو بيانات مستخدم؛ مع اشتراط HTTPS في الإنتاج واستثناء HTTP المحلي للتطوير |
| `BLOG_RP_ID` | اسم المضيف الدقيق المأخوذ من `BLOG_BASE_URL` دون أي توسيع ليشمل النطاق الأب |
| `BLOG_WEBAUTHN_ORIGINS` | أصل النطاق المهيأ نفسه مفصولاً بفواصل؛ ولا يتيح هذا النموذج إمكانية فتح أصول متباينة |
| `BLOG_DATA_ROOT` | مسار مطلق إلزامي خارج شجرة المستودع، وخارج مجلد الإصدار الفعال، ومجلد الواجهة؛ وتُحل أسلاف الروابط الرمزية الموجودة؛ ويحظر تقديم هذا المجلد مباشرة للعامة |
| `BLOG_FRONTEND_DIST` | يُفضل مساراً مطلقاً؛ والقيمة الافتراضية هي `../frontend/dist` نسبةً لمجلد العمل؛ ويشترط وجود بيان الأصول (manifest) في الإنتاج |
| `BLOG_LISTEN_ADDR` | عنوان IP ورقم المنفذ صراحة؛ والقيمة الافتراضية هي `127.0.0.1:8080`، ويتولى الخادم الوكيل التعامل مع اتصالات HTTPS الخارجية |
| `BLOG_TRUSTED_PROXIES` | فارغ افتراضياً، أو يضم نطاقات CIDR لعناوين IP الخاصة بنظراء الوكيل الفعليين مفصولة بفواصل |

يتجاهل فاحص عنوان IP للعميل ترويسات التمرير القادمة من نظراء غير موثوقين. وفي حال كان النظير موثوقاً، يتم تقييد ترويسة `X-Forwarded-For` والتحقق منها وفحصها من اليمين إلى اليسار حتى الوصول لأول قفزة شبكية غير موثوقة. وتؤدي القوائم المشوهة إلى الرجوع لعنوان النظير المباشر. ولا يحل اسم المضيف أو البروتوكول الممرر في الترويسات محل النطاق الأساسي أو معرف RP ID المهيأين في النظام. اضبط الخادم الوكيل لاستبدال عنوان النظير الفعلي أو إلحاقه بصورة صحيحة. وتعتمد آليات تقييد معدل محاولات المصادقة على هذا الفاحص وحده وليس على الترويسات الخام. وتتولى خدمة المصادقة تنفيذ التحقق من معيار WebAuthn، وتطابق أصل النطاق، وفحوصات الحماية من CSRF.

توفر أدوات التطوير المحلي إعدادات الاسترجاع المحلي (loopback) ومجلداً مؤقتاً خاصاً بالبيانات ما لم يتم تعيين المتغير `BLOG_DATA_ROOT`. وقد يقوم نظام التشغيل بمسح بيانات التطوير المؤقتة؛ لذا احذر من استخدامها في بيئة الإنتاج. وبعد إتمام بناء المشروع، يمكن بدء التشغيل الإنتاجي من المجلد الجذري للمستودع عبر:

```sh
BLOG_ENV=production \
BLOG_BASE_URL=https://blog.example \
BLOG_RP_ID=blog.example \
BLOG_WEBAUTHN_ORIGINS=https://blog.example \
BLOG_DATA_ROOT=/var/lib/personal-blog \
BLOG_FRONTEND_DIST="$PWD/frontend/dist" \
./build/blog
```

استخدم مجلداً خاصاً موجوداً مسبقاً وقابلاً للكتابة ومملوكاً لحساب خدمة التطبيق. للاطلاع على خطوات إعداد خادم VPS الكاملة وأوامر الترقية، اتبع [دليل النشر](../../deploy/README.ar.md). وتتوفر إرشادات إعداد قاعدة البيانات وقواعد النسخ الاحتياطي الإلزامية قبل الترحيل في [دليل ترحيلات SQLite](../../backend/migrations/README.ar.md).

## حدود التفويض المشتركة والتحقق

تحدد حزمة `internal/access` هوية الفاعل، وسطح الاستدعاء، والعملية/اللغة/المورد، وقرارات الرؤية المحددة الأنواع للمحتوى، والوسائط، والمعاينات، والبحث، والخلاصات، والمجموعات. ويرفض القرار الصفري الافتراضي وقرار `DenyAll` وصول كافة الفئات. ولا يمنح قرار الملخص العام `PublicTeaser` حق الوصول لمتن المحتوى إطلاقاً. وتقوم السياسة الحية بحل حالة النشر والخطة النشطة باتساق للمحتوى، والوسائط، والبحث، والمجموعات؛ فلا يكفي مجرد توفر عنوان URL أو وجود مرجع وسائط منشور لمنح الوصول. وتظل الدروس ذات الخطط المفقودة أو غير المدعومة مقفلة؛ وتتولى قواعد الاختبارات والمتعلمين توسيع هذه الحدود.

شغّل الأمرين `go test ./...` و`go vet ./...` داخل مجلد `backend/`. تغطي الاختبارات حدود المدخلات، والمسارات المفقودة، وانتحال الوكيل، والتحقق من أصل النطاق والمسارات، وحظر مسارات الالتفاف والروابط الرمزية للأصول، وفشل الجاهزية، وخلو الاستجابات والسجلات من الأسرار. وبعد البناء المعتاد وتثبيت أداة Playwright، يقوم سكربت `node scripts/smoke-production.mjs` بتشغيل ملف Go التنفيذي وحده، وفحص الواجهة وAPI والأصول على أصل النطاق نفسه، ثم تشغيل مصفوفة لغات ومظاهر المتصفح مقابل هيكل الصفحة وسياسة أمان المحتوى (CSP) الحقيقيين. علماً بأن بيئة الاختبارات تستخدم Node، بينما لا يحتاج التطبيق الخادم إليها في الإنتاج.

تتوفر تفاصيل مسارات المصادقة وحمولاتها في وثيقة: [واجهة برمجة المالك](owner.ar.md). ويحدد المتغير الاختياري `BLOG_AUTH_KEY_FILE` ملفاً ثنائياً خاصاً بطول 32 بايت خارج جذر البيانات؛ راجع دليل تهيئة المالك.
