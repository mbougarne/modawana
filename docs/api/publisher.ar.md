# الناشر المحدود الصلاحيات وأداة Go لسطر الأوامر

[English](publisher.md) · [فهرس API](README.ar.md) · [مشغّل التسليم](../integrations/lesson-delivery.ar.md)

تتيح شاشة أمان المالك (Owner Security) إنشاء رموز مميزة مسمّاة ذات صلاحيات مستقلة هي: المسودة `draft`،
والوسائط `media`، والاختبارات `quiz`، والنشر `publish`. اختر مفاتيح المجموعات المصرح بها؛ في حين تتطلب
المقالات الواقعة خارج المجموعات تصريحاً إضافياً صريحاً. يتطلب إنشاء الرمز مصادقة كاملة للمالك تمت خلال
الدقائق الخمس الأخيرة، مع إعادة فحص ذلك داخل معاملة قاعدة البيانات. تعتمد واجهة المستخدم افتراضياً صلاحية
المسودات فقط مع انتهاء الصلاحية بعد 90 يوماً؛ بينما تقبل واجهة برمجة التطبيقات مدة تتراوح بين 1 و365 يوماً.
يمكن تفعيل 50 رمزاً كحد أقصى (غير منتهية الصلاحية وغير ملغاة). ولا يُخزن في قاعدة البيانات سوى تجزئة SHA-256
للرمز. احفظ السر المعروض في مخزن أسرار المشغّل الخاص بك؛ فالعمليات اللاحقة لن تعيد عرضه أبداً. ويمكن إعادة
تسمية الرمز أو إلغاؤه في أي وقت من شاشة الأمان.

المسار `/api/v1/security/publisher-tokens`: يُرجع طلب GET البيانات الوصفية، ويقبل POST الحمولة
`{label,scopes,collections,allow_articles,days}` ويُرجع البيانات الوصفية مع السر `secret` لمرة واحدة فقط،
ويقبل PATCH الحمولة `{id,label}`، ويقبل DELETE الحمولة `{id}`. تستخدم هذه المسارات ملف تعريف ارتباط المالك
وحدود Origin وCSRF المعتادة. ولا يمكن لرموز الناشر إنشاء بيانات اعتماد جديدة أو التحول إلى جلسات مالك أو جلسات تعلم.

## مسارات الآلة البرمجية

تستخدم مساحة المسارات المخصصة للآلات `/api/v1/publisher/` الترويسة `Authorization: Bearer …` ولا تعتمد
على ملفات تعريف ارتباط المتصفح إطلاقاً. وتُرفض أي معاملات استعلام (query strings). ولا يجوز وضع بيانات
الاعتماد في الروابط، أو ملفات Markdown، أو حزم البرامج، أو سجلات التشغيل. وتستدعي هذه المسارات خدمات المحتوى
والوسائط ذاتها المستخدمة في واجهة المالك، مع التحقق الصارم من حالة إلغاء الرمز، وصلاحياته، وقيود المجموعات
المفروضة داخل معاملات التعديل الذرية.

| المسار | الصلاحية والسلوك البرمجي |
| --- | --- |
| `GET /content/{key}/{locale}` | `draft`؛ قراءة المسودة الحالية المسموح بها لمطابقتها. وتتطلب المسودات التي تحوي اختباراً صلاحية `quiz` إضافية. |
| `PUT /content/{key}/{locale}` | `draft`؛ يقبل كائن JSON للمسودة ذاته المعتمد في واجهة المالك. وتتطلب إضافة أو تعديل أو إزالة أي اختبار صلاحية `quiz`. |
| `POST /content/{key}/{locale}/publish` | `publish`؛ يقبل الحقلين `{expected_version,revision_id}` المحددين بدقة. وتظل قيود مراجعة الترجمة والتقييم النشط ملزمة ونافذة؛ ولا يتم تطبيق خطط المسارات عبر هذا المسار. |
| `POST /media` | `media`؛ طلب متعدد الأجزاء يتضمن جزءاً واحداً للملف `file` لغرض المحتوى فقط. يمكن ربط الملفات المرفوعة بواسطة الرمز أو الوسائط المرتبطة مسبقاً بمجموعة أو مقال مسموح به بالمسودات. |

المسارات المذكورة في الجدول نسبية إلى البادئة `/api/v1/publisher`. تتطلب كافة عمليات الكتابة ترويسة مفتاح عدم
التكرار `Idempotency-Key`؛ وتُرجع إعادة الطلب المطابق النتيجة المسجلة ذاتها لمدة سبعة أيام، بينما يؤدي استخدام
المفتاح نفسه مع حمولة مختلفة إلى إرجاع الرمز 409. كما تُرجع تعارضات إصدارات المسودات أو النشر الرمز 409 أيضاً.
يتعين مطابقة الحالة وجلبها عبر GET أولاً قبل إعداد عملية جديدة عمداً؛ وتجنب رفع رقم الإصدار المتوقع تلقائياً
عند وقوع تعارض. ويصبح إلغاء الرمز نافذاً على الفور حتى بالنسبة للمحاولات المعاد إرسالها.

لا تملك الرموز صلاحية مراجعة واعتماد الترجمات أو التقييمات، ولا تعديل بوابات الدروس، ولا تطبيق الخطط،
ولا إعادة ضبط التقدم، ولا تغيير الهوية البصرية أو آليات المصادقة، ولا انتحال شخصية متعلم. ولا يمكن لأي رمز
استبدال تقييم مختلف وراء بوابة عبور نشطة؛ حيث يتولى المالك وحده مراجعة التقييم الجديد ونشره صراحة مع خطة
محفوظة ومطابقة.

تتحكم صلاحية `quiz` في الوصول إلى مفاتيح إجابات المسودات وتعديل أسئلة الاختبار؛ بينما تتيح صلاحية `publish`
بشكل مستقل نشر مراجعة محفوظة محددة بدقة تقع ضمن النطاق المصرح به، بما في ذلك المواد التي تتضمن اختبارات.
ولا يمنح النشر إمكانية الاطلاع على مفاتيح الإجابات، أو تعديل الاختبار، أو صلاحية المراجعة. وتظل كافة فحوص
مراجعة الترجمات وتقييمات البوابات النشطة سارية بالكامل.

## أداة سطر الأوامر (CLI)

تُبنى الأداة باستخدام الأمر `node scripts/project.mjs build`. ويزود المشغّل متغيري البيئة `BLOG_URL` و
`BLOG_PUBLISHER_TOKEN` من خلال بيئة الأسرار الخاصة به. ويشترط استخدام بروتوكول HTTPS حصراً، باستثناء
عناوين IP الحلقية (loopback) الحرفية في الاختبارات. ويمكن لمتغير البيئة الاختياري `BLOG_PUBLISHER_CA`
تحديد ملف شهادة PEM موثوق؛ وهو لا يعطل التحقق من الشهادات أبداً. ولا تتبع الأداة عمليات إعادة التوجيه
(redirects)، ولا تقبل تمرير رمز النشر كوسيط ضمن سطر الأوامر إطلاقاً.

```sh
build/publisher upload --file image.webp --mime image/webp --idempotency lesson-001-image
build/publisher draft --key lesson-001 --locale en --input draft.json --markdown lesson.md --idempotency lesson-001-draft
build/publisher get --key lesson-001 --locale en
build/publisher publish --key lesson-001 --locale en --revision SAVED_REVISION_ID --expected-version 1 --idempotency lesson-001-publish
```

يستخدم الملف `draft.json` مخطط `DraftInput` المعتمد للمالك: الإصدار المتوقع `expected_version` (القيمة 0
للمحتوى الجديد)، ونوع المحتوى، ولغة المصدر، والاسم اللطيف (slug)، والعنوان، والملخص الاختياري، ومفتاح المجموعة
وموضع الدرس/الوثيقة، والاختبار الاختياري، ومراجع الوسائط، ومراجعة المصدر في حالات الترجمة. ويزود الخيار
`--markdown` متن المحتوى من ملف مستقل. وتكون المخرجات بتنسيق JSON متضمنة معرّفات مراجعات ثابتة وإصدارات،
أو أخطاء مهيكلة بالحالة والرمز من واجهة API؛ وتشير حالة الخروج 1 إلى حدوث فشل. وتتم إعادة محاولة العملية
المنقطعة باستخدام الحمولة والمفتاح ذاتهما.

## مشغّل الناشر المحلي

احفظ القيم التالية فقط في الملف `~/.config/modawana/publisher.env` خارج مستودع Git، مع ضبط
أذونات الدليل على 0700 وأذونات الملف على 0600:

```sh
BLOG_URL=https://blog.example
BLOG_PUBLISHER_TOKEN='PASTE_YOUR_BLOG_TOKEN_HERE'
```

استبدل النص المؤقت بالسر الحقيقي في سرية تامة. ويمكن لمتغير `BLOG_PUBLISHER_CA` الاختياري تحديد ملف
شهادة PEM موثوق. إياك وعرض هذا الملف، أو طباعة متغيرات البيئة، أو تفعيل تتبع أوامر الصدفة (shell tracing)،
أو وضع الرمز السري في نص موجه (prompt)، أو كوسيط أمر، أو ضمن جدول زمني. يحلل مشغّل Node بيانات ملف dotenv
دون تنفيذ أي تعبيرات برمجية للصدفة، ويرفض الروابط الرمزية، والملفات المتاحة للمجموعات أو للمستخدمين الآخرين،
والملفات المملوكة لمستخدمين آخرين، وأسماء ملفات التهيئة غير المتوقعة؛ ثم يمرر بيانات الاعتماد إلى أداة ناشر Go
حصراً عبر بيئة العملية التابعة (child process). ويحد ذلك من فرص التسريب العرضي؛ لكنه لا يحجب الملف عن
الأدوات أو المستخدمين الذين يملكون بالفعل وصولاً مباشراً لنظام الملفات.

ابنِ الملف التنفيذي لمنصتك من جذر المستودع (لا حاجة لإعادة البناء على خادم VPS):

```sh
cd backend
go build -trimpath -o ../build/publisher ./cmd/publisher
cd ..
node scripts/publish.mjs --check
```

يتحقق الخيار `--check` من صحة الإعدادات المحلية وتوفر الملف التنفيذي دون إجراء أي طلب شبكي. وهو لا يتحقق
من صلاحية الرمز، أو نطاق أذوناته، أو تاريخ انقضائه. مرر وسائط سطر الأوامر المعتادة إلى السكربت
`node scripts/publish.mjs`، على سبيل المثال:

```sh
node scripts/publish.mjs get --key EXISTING_CONTENT_KEY --locale en
node scripts/publish.mjs draft --key lesson-001 --locale en --input draft.json --markdown lesson.md --idempotency lesson-001-draft
```

لإنشاء مسودة حقيقية، جهّز البيانات الوصفية الموثقة وملف Markdown أولاً واحتفظ بالمدخلات ومفتاح عدم التكرار
نفسهما عند إعادة المحاولة. وابدأ بقراءة عنصر مسموح به موجود إن وُجد. ولا تستخدم مفتاح محتوى غير موجود لاختبار
المصادقة: إذ تُفحص الصلاحيات قبل البحث عن المسودة وقد تُرجع الرمز 403 بدلاً من 404. ويُرجع الرمز غير الصالح
أو منتهي الصلاحية أو الملغى رمز الحالة 401. ولا يُعد الرمز 403 دليلاً على السماح بكافة الصلاحيات أو المجموعات المطلوبة.

لإجراء اختبار متعمد ومضبوط لمسودة خاصة، يحتاج الرمز إلى صلاحية `draft` وتصريح للمقالات الواقعة خارج
المجموعات. ولا يتم استيراد بيانات الاختبار التجريبية هذه تلقائياً مطلقاً:

```sh
node scripts/publish.mjs draft --key publisher-connection-check --locale en --input scripts/fixtures/publisher-check.json --markdown scripts/fixtures/publisher-check.txt --idempotency publisher-connection-check-v1
node scripts/publish.mjs get --key publisher-connection-check --locale en
```

يؤدي هذا إلى إنشاء مقال اختباري واحد غير منشور، وليس منشوراً عاماً. وتؤدي إعادة تنفيذ أمر المسودة المطابق
إلى إعادة استخدام مفتاح عدم التكرار ذاته. توقف فوراً عند حدوث تعارض في الإصدارات؛ ولا تكتب فوق عنصر موجود
أو ترفع أرقام الإصدارات تلقائياً. يمكنك فحص المسودة المنشأة في شاشة المقالات التابعة للمالك. ويختبر هذا
الإجراء صلاحية الوصول لمسودات المقالات، ولا يختبر أذونات الوسائط، أو الاختبارات، أو النشر، أو مسارات التعلم.

يتطلب النشر مطابقة مراجعة وإصدار محفوظين ومحددين بدقة، وطلب نشر مرخصاً أو سياسة دروس مهيأة للغة الأصلية؛
فامتلاك صلاحية الرمز وحدها لا يخول نشر أي نص بصورة عشوائية. وتظل أذونات المجموعات، ومراجعة المالك للترجمات
والتقييمات، وبوابات الدروس سارية ونافذة.

لا يمكن لأي مهمة أتمتة محلية استدعاء هذا المشغّل إلا إذا سمحت أذونات نظام الملفات والشبكة الخاصة بها بقراءة
التهيئة الخاصة، وتنفيذ أداة الناشر، والوصول إلى أصل HTTPS. وبيانات الاعتماد المحفوظة على جهاز معين ليست
متاحة تلقائياً لمحادثة أخرى، أو لمشغّل سحابي، أو لدرس مجدول. وهذا المشغّل ليس خادم MCP. راجع
[نقطة تحقق التسليم](../integrations/lesson-delivery.ar.md) قبل تعديل الجداول الزمنية الحالية. واختبر آلية
التعامل مع بيانات الاعتماد عبر الأمر: `node --test scripts/publish.test.mjs`.

التحقق والضمان: تغطي اختبارات Go حداثة المصادقة، وتخزين التجزئات، وعزل المجموعات والاختبارات، والتعامل مع
بيانات الاعتماد الملغاة، والتعارضات، وإعادة التشغيل المطابقة، ومحاولات تصعيد الصلاحيات. وتختبر حزمة اختبارات
المتصفح على الخادم الحقيقي واجهة إدارة الرموز باللغات الإنجليزية والعربية والفرنسية، بالإضافة إلى عمليات رفع
الوسائط والمسودات وإعادة المحاولة والنشر المحدد والإلغاء الفعلية عبر أداة Go. ولا يتم إنشاء أو استخدام أي
بيانات اعتماد أو محتوى إنتاجي في البيئات التجريبية.

## خادم MCP البعيد والتوليد المجدول

استخدم [بروتوكول MCP مع OAuth](../integrations/mcp-oauth.md) للعملاء البعيدين المدعومين، و
[أداة الجدولة](../integrations/remote-publishing.md) لتوليد الدروس المجدولة اختيارياً. وتعيد كلاهما استخدام
صلاحيات الناشر المحددة؛ بينما تظل بيانات اعتماد توليد الذكاء الاصطناعي منفصلة ومستقلة.

يعتمد المشغّل افتراضياً المسار `~/.config/modawana/publisher.env`. ويمكن للتثبيتات القائمة الإبقاء على
ملفها الخاص الحالي عن طريق تعيين متغير البيئة `BLOG_PUBLISHER_CONFIG` إلى مساره المطلق قبل تشغيل المشغّل.
ولا يتم نقل بيانات الاعتماد تلقائياً إطلاقاً.
