# واجهة برمجة تطبيقات المالك

[English](owner.md) · [فهرس API](README.ar.md) · [دليل التشغيل](../owner-security.ar.md)

جميع المسارات الموضحة أدناه نسبية إلى البادئة `/api/v1`. تستخدم استجابات JSON ترويسة `Cache-Control: no-store`،
وتعتمد الأخطاء غلاف الاستجابة المشترك. يبلغ الحد الأقصى لحجم حمولة المدخلات 64 KiB. وتُعد أجسام الطلبات
التي تتضمن مدخلات كائنات محددة الأنواع بدقة (strict typed objects) باستثناء طلبات WebAuthn التي تعتمد
تنسيق JSON القياسي لبيانات الاعتماد وفق مواصفات المكتبة. ولا يُعاد في الاستجابات أي مسار فيزيائي على الخادم،
أو مفتاح خاص، أو رمز ملف تعريف ارتباط، أو بذرة تشفيرية.

| الطريقة والمسار | المدخلات ← حمولة النجاح | متطلبات الصلاحية والمصادقة |
| --- | --- | --- |
| `POST /auth/start` | `{}` ← `{state:"anonymous",csrf}` وملف ارتباط مقيد | ترويسة Origin مطابقة بدقة، و`X-Blog-Request: 1`؛ مع حظر CORS |
| `GET /session` | ← `{state,csrf?,session?}`؛ الحالات: anonymous أو bootstrap أو recovery أو password أو managed أو owner | ملفات الارتباط الحالية؛ لا ينشئ أي تصريح جديد |
| `POST /auth/grant` | `{grant,email}` ← `{state:"enrollment",csrf}` وتدوير ملف الارتباط المقيد | تدفق مجهول مع رمز CSRF؛ تصريح محلي صالح لمرة واحدة |
| `POST /auth/passkeys/login/options` | `{}` ← `{publicKey:…}` | تدفق مجهول مع رمز CSRF |
| `POST /auth/passkeys/login/verify` | كائن إثبات المتصفح (assertion JSON) ← `{state:"owner",csrf}` | تحدٍ مطابق صالح لمرة واحدة؛ يضبط ملف ارتباط مالك مدوَّراً |
| `POST /auth/passkeys/register/options` | `{}` ← `{publicKey:…}` | تدفق التهيئة/الاسترداد، أو مصادقة مالك حديثة مع تدفق مجهول |
| `POST /auth/passkeys/register/verify` | كائن تسجيل المتصفح (attestation JSON)؛ ترويسة `X-Passkey-Label` هي `encodeURIComponent(name)` ← `{state:"sign_in_to_test"}` | التدفق المقيد نفسه، مع اشتراط مصادقة مالك حديثة عند الإضافة المدارة؛ لا تمنح عملية التسجيل جلسة مالك كاملة |
| `POST /session` | `{email,password}` ← `{state:"password",csrf}` | تدفق مجهول مع رمز CSRF؛ دون منح ملف ارتباط كامل |
| `POST /session/totp` | `{code}` ← `{state:"owner",csrf}` | تدفق بانتظار التحقق من كلمة المرور مع رمز CSRF |
| `POST /session/recovery` | `{code}` ← `{state:"owner" أو "recovery",csrf}` | تدفق بانتظار كلمة المرور عند توفر عامل بديل؛ وإلا يقتصر على إعادة تسجيل مقيدة |
| `DELETE /session` | `{}` ← `{ok:true}` | جلسة مالك مع رمز CSRF؛ يلغي ملف ارتباط الجلسة الحالية |
| `GET /security/passkeys` | ← `[{id,label,created_at,last_used_at,tested_at}]` | جلسة مالك |
| `PATCH /security/passkeys` | `{id,label}` ← `{ok:true}` | مصادقة مالك حديثة مع رمز CSRF |
| `DELETE /security/passkeys` | `{id}` ← `{ok:true}` | مصادقة مالك حديثة مع رمز CSRF؛ يشترط وجود وسيلة أخرى مجربة؛ ويلغي كافة الجلسات |
| `GET /security/factors` | ← `{totp_enabled,totp_available,login_email,recovery_codes_remaining}` | جلسة مالك؛ البريد الإلكتروني سري ولا يُعد جزءاً من الملف العام |
| `POST /security/totp/options` | `{password}` ← `{secret}` وملف ارتباط تسجيل مقيد | مصادقة مالك حديثة مع رمز CSRF، وتهيئة مفتاح التشفير الخارجي |
| `POST /security/totp/verify` | `{code}` ← `{state:"sign_in"}` | جلسة المالك والتدفق ذاتهما مع بذرة مشفرة معلقة؛ يفعّل العامل ويلغي الجلسات النشطة |
| `DELETE /security/totp` | `{}` ← `{ok:true}` | مصادقة مالك حديثة مع رمز CSRF؛ يشترط وجود وسيلة مصادقة أخرى مجربة |
| `POST /security/recovery-codes` | `{}` ← `{codes:[10 strings]}` لمرة واحدة فقط | مصادقة مالك حديثة مع رمز CSRF؛ يستبدل كافة الرموز السابقة |
| `GET /security/sessions` | ← `[{id,method,authenticated_at,created_at,expires_at}]` | جلسة مالك؛ استرجاع حتى 100 جلسة نشطة |
| `DELETE /security/sessions` | `{id?}` ← `{ok:true}`؛ يؤدي إغفال المعرّف أو تركه فارغاً إلى إلغاء جميع الجلسات | مصادقة مالك حديثة مع رمز CSRF |
| `GET /security/events` | ← `[{event,request_id,created_at}]` | جلسة مالك؛ أحدث 100 حدث من بين 1000 حدث كحد أقصى يتم الاحتفاظ بها |

تتطلب جميع عمليات الكتابة اللاحقة لمسار `/auth/start` وجود ترويسة Origin مطابقة بدقة وترويسة `X-CSRF-Token`
مرتبطة بملف تعريف الارتباط الخاص بها. وتعتمد مسارات الأمان وتسجيل الخروج رمز CSRF الخاص بالمالك؛ بينما تستخدم
إجراءات المصادقة رمز CSRF الخاص بالتدفق المقيد. ولا تنشئ طلبات GET العامة أي حالة مصادقة في النظام. وتصف
الحالة `state` مرحلة المصادقة الحالية فقط، ولا تمثل إثباتاً على وجود نقاط نهاية لنشر المحتوى أو الوصول المستقبلي.
كما يُعاد التحقق الصارم من شرط حداثة المصادقة (خلال 5 دقائق) داخل معاملات قاعدة البيانات الحساسة.

يُشير رمز الحالة 401 إلى فشل المصادقة العام، و403 إلى رفض الوصول أو الحاجة إلى مصادقة حديثة، و409 إلى تعارض
في عوامل المصادقة، و429 إلى تقييد معدل المحاولات (مع ترويسة `Retry-After: 900`)، و503 إلى تعذر الوصول إلى
مفتاح أو خدمة المشغّل الخارجية، و500 إلى حدوث خطأ داخلي. وتفشل طلبات المصادقة غير الصالحة برسائل خطأ موحدة
وعامة لتجنب كشف وجود البريد الإلكتروني أو عوامل المصادقة من عدمه. كما أن الاستجابة الفاشلة أو المفقودة لطلب
تعديل لا تُعد دليلاً على نجاحه؛ لذا يلزم إعادة تحميل حالة الصفحة قبل إعادة المحاولة. وتُستخدم تحديات مفاتيح
المرور (passkey challenges) لمرة واحدة فقط حتى في حال فشل التحقق، وتنقضي صلاحيتها بعد خمس دقائق. وتظل الرموز
والبذور التشفيرية محصورة في حالة واجهة المستخدم العابرة فقط ولا تُخزن في `localStorage` إطلاقاً.

## التغذية الراجعة لإجراءات المالك

يمكن لعمليات الحساب والأمان إرجاع قائمة أخطاء بالحقول `error.fields: [{path,code}]` باستخدام مسارات مخطط آمنة:
`security.label`، و`security.password`، و`security.code`، و`security.passkeys`،
و`security.request`، و`security.token_*`. توضح رموز الأسباب قيود التسمية وكلمة المرور، وإعدادات المصادقة
غير الصالحة أو منتهية الصلاحية، وقيود إدخال الرموز، واشتراطات الإبقاء على عامل مصادقة أخير أو وجود مفتاح مرور
مختبر مسبقاً. تُرجع أخطاء المدخلات رمز الحالة 422، ويُرجع منع حذف العامل الأخير 409، وتُرجع الكتابة غير
المؤكدة 403. وتظل فحوص الجلسة والحداثة، وحدود المعدل، والمعاملات الذرية، وأخطاء بيانات الاعتماد المجهولة
الموحدة سارية دائماً. ولا يُعاد أي نص لكلمة المرور، أو البذرة المشفرة، أو الرمز، أو معرّف الاعتماد في تفاصيل أخطاء التحقق.

### التغذية الراجعة لمراجعة التقييمات

يؤدي غياب المراجعة الصريحة للتقييم المحدد إلى إرجاع الرمز HTTP 422 بالرسالة `invalid_fields` وسبب الحقل الآمن:
`{ "path": "quiz", "code": "assessment_review" }`. وتحتفظ أسباب حقول المجموعات الحالية بمساراتها ورموزها
الأكثر تخصصاً. وتظل عمليتا معاينة الاختبار ومراجعته عمليتين محميتين بصلاحيات المالك وترويستي Origin وCSRF
على مراجعة المحتوى المحفوظة بدقة؛ ولا تؤدي أي منهما إلى نشر المحتوى أو تسجيل أي تقدم تعليمي في متصفح القارئ.
كما تظل بوابة الفتح المحفوظة خاصة ومحجوبة إلى أن يتم تفعيل خطة المسار صراحة من قِبل المالك.
