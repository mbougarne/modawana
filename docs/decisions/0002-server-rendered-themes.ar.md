# القرار المعماري 0002: صفحات عامة مولّدة على الخادم وحزم سمات

[English](0002-server-rendered-themes.md) · [القرارات](README.ar.md) · [الصفحات العامة](../public-pages.ar.md)

- الحالة: معتمد
- التاريخ: 2026-11-01
- صاحب القرار: المالك (مراد بوقرن)
- حالة الترجمة: بانتظار مراجعة لغوية من متحدث أصلي

## السياق

الصفحات العامة اليوم تطبيق React أحادي الصفحة (SPA). يولّد خادم Go بالفعل
هيكل HTML عبر قالب `html/template` (`backend/internal/http/server.go`):
بيانات وصفية مهرَّبة، ووسوم Open Graph، وبدائل `hreflang`، وCSS لوحة الألوان،
وكتلة JSON للإقلاع — ثم `<div id="root">` فارغ. ولا يزال متن المقال يحتاج
JavaScript ([الصفحات العامة](../public-pages.ar.md)).

الحقائق التي تشكّل هذا القرار:

- الدالة `content.Service.ResolvePage`‏ (`backend/internal/content/routes.go`)
  هي بالفعل العقد العام الوحيد المشترك بين تسليم HTML وتنقّل SPA. تعيد نموذج
  عرض `PageRoute` محايداً تجاه المولّد، وتقرر 200/403-مقفل/404/503 قبل أي
  توليد.
- يتحول Markdown إلى HTML في المتصفح فقط (`react-markdown` و`remark-gfm`
  و`remark-math` و`rehype-katex`، مع مولدات الوسائط والروابط والشيفرة
  المخصصة المحددة في [عقد قارئ Markdown](../markdown-reader.ar.md)). ولا
  يستخدم الخادم goldmark إلا للتحقق وجمع مراجع الوسائط.
- لوحة الألوان ومنطق بطاقة المشاركة مكرران بين Go وTypeScript؛ وسياسة CSP
  صارمة وقائمة على القيم العشوائية (nonce)؛ وكل استجابة `no-store` لأن الوصول
  مرتبط بهوية المتعلم.
- لا توجد اليوم خلاصات ولا خريطة موقع؛ وكلاهما يحتاج مخرجات مولّدة على الخادم.

نظام السمات (تصاميم يختارها المالك، ثم حزم قابلة للتثبيت من قوالب وCSS
وأصول) لا يمكن بلوغه من SPA مُجمَّع عبر Webpack.

## القرار

نقل الصفحات العامة من React SPA إلى قوالب Go مولّدة على الخادم، صفحة صفحة،
خلف عناوين URL نفسها وعقد `ResolvePage` نفسه. يبقى تطبيق React لوحة تحكم
المالك. **السمة** حزمة من قوالب Go وCSS وأصول ثابتة تولّد نماذج العرض
العامة. تُشحن ثلاث سمات مدمجة مُجمَّعة داخل الملف التنفيذي؛ ويختار المالك
إحداها في الإعدادات. تبقى ميزات التعلم التفاعلية جزراً من JavaScript تُركَّب
داخل الصفحات المولّدة على الخادم. ولا يتغير ضبط الوصول، ولا رموز الحالة،
ولا الإسقاطات المقفلة، ولا سلوك `noindex`.

## الحد الفاصل بين المضيف والسمة

| الطرف | يملك |
| --- | --- |
| الخادم (Go) | التوجيه، وقرارات الوصول، ورموز الحالة، وتجميع نماذج العرض، وتحويل Markdown إلى HTML، والتعقيم، وقيم CSP العشوائية، وترويسات التخزين المؤقت، وتراجع التسميات واللغات |
| السمة | التخطيط والعرض: قوالب فوق نماذج العرض، وCSS مبني على رموز نظام التصميم، وأصول ثابتة |

- لا تتلقى القوالب إلا إسقاطات عامة آمنة: `PageRoute` و`siteconfig.Public`
  والتسميات المحلولة وHTML المتن المولّد. لا مقابض قاعدة بيانات، ولا أسرار،
  ولا مسودات أو محتوى مبوّب — فلا يمكن لقالب أن يسرّب ما لا يحتويه نموذج
  العرض. ويبقى نموذج عرض 403-المقفل هو إسقاط المقتطف الآمن.
- السمات **بلا JavaScript وبلا شيفرة Go**. تأتي التفاعلية من حزم جزر يملكها
  المضيف وموسومة بقيم عشوائية؛ والقوالب المدمجة مُجمَّعة عبر `embed`،
  والحزم الخارجية (مرحلة لاحقة) ملفات مُتحقَّق منها وذات مجاميع اختبارية تحت
  جذر البيانات، تُثبَّت مثل الإضافات (القرار [0001](0001-wasm-plugin-host.ar.md)).
- يستخدم CSS السمات رموز نظام التصميم والخصائص المنطقية، فتعمل العربية من
  اليمين إلى اليسار، والوضعان الفاتح والداكن، وعلامة المالك التجارية في كل
  سمة. يبقى `design-system/tokens.json` مصدر الحقيقة، وتستمر `Palette.CSS()`
  في بث تجاوزات ألوان المالك داخل الهيكل.
- اختيار السمة حقل جديد في مستند إعدادات `site` الحالي، فيكون مُدار
  الإصدارات وقابلاً للمعاينة والاستعادة، ولا يحتاج نوع إعدادات جديداً
  (مجموعة `config_documents.kind` مغلقة بقيد CHECK).

## تكافؤ توليد Markdown (الخطر الرئيسي)

يتطلب التوليد على الخادم خط أنابيب Go لتحويل Markdown إلى HTML بتكافؤ تام مع
[عقد قارئ Markdown](../markdown-reader.ar.md): GFM، وسياسة الروابط الآمنة،
وصور/فيديو/تعليقات/أغلفة الوسائط بمعرفاتها، وروابط PDF، والعروض التقديمية،
وكتل الشيفرة (من اليسار إلى اليمين داخل الصفحات العربية)، والخلاصات — ودون
HTML خام.

- يُبنى على goldmark (اعتمادية خلفية موجودة أصلاً للتحقق)، مع مولدات مخصصة
  لامتدادات الوسائط والسياسات.
- الرياضيات: لا يوجد KaTeX بلغة Go. تبقى الرياضيات تحسيناً على جانب العميل —
  يبث الخادم مصدر TeX في عناصر موسومة ولا يضمّن جزيرة KaTeX إلا في الصفحات
  التي تحتوي رياضيات. والمحتوى الخالي من الرياضيات (وهو الأغلب) يُشحن دون أي
  JavaScript للتوليد.
- يُفرض التكافؤ بعيّنات مشتركة: كل تركيب في العقد له عيّنة يولّدها الخطان
  وتُقارن في CI ما دام الخطان موجودين. يُزال خط المتصفح صفحة صفحة مع انتقال
  الصفحات، ثم كلياً حين لا تبقى أي صفحة عامة في SPA.

## التفاعلية جزراً

يبقى مشغّل الاختبارات، والتقدم، وعلامة «تمت القراءة»، والبحث الحي JavaScript،
وفي البداية ميزات React الحالية (`ReaderLearning` و`BrowserProgress` والبحث)
مركّبةً جزراً داخل الصفحات المولّدة على الخادم، تستدعي واجهات التعلم نفسها
بقواعد CSRF/الأصل نفسها. هذا يجنّب إعادة بناء واجهة قريبة من التصحيح أثناء
الانتقال. وتنحيف الجزر لاحقاً تحسين، لا جزءاً من هذا القرار. كل نصوص الجزر
أصول مذكورة في البيان وموسومة بقيم عشوائية؛ وتبقى CSP صارمة دون نصوص أو
أنماط مضمنة خارج كتلة العلامة التجارية الموسومة الحالية.

## النموذج الأمني

- يُقرَّر الوصول في Go قبل تشغيل أي قالب؛ وتولّد القوالب الإسقاط الآمن
  للقرار. لا تستطيع سمة تحويل درس مقفل إلى مقروء لأن HTML المتن للمحتوى
  المقفل لا يوجد أصلاً.
- التهريب السياقي في `html/template` مع HTML متن معقّم يولّده المضيف؛
  القوالب تُدرج بيانات ولا تركّب HTML خاماً.
- يبقى التخزين المؤقت `no-store` في هذه المرحلة. التخزين الانتقائي للصفحات
  العامة المجهولة قرار لاحق منفصل؛ والصفحات المبوّبة والمرتبطة بالمتعلم تظل
  غير قابلة للتخزين المؤقت بموجب العقد.
- حزم السمات الخارجية (لاحقاً): يثبتها المالك بمجاميع اختبارية مسجلة في
  SQLite، مع تحليل قوالب بمجموعة دوال مقيدة، وحدود حجم، ودون أي قدرة على
  إضافة مسارات أو نصوص برمجية أو جلب موارد بعيدة.

## التخزين والأثر على النسخ الاحتياطي والاستعادة

- السمات المدمجة داخل الملف التنفيذي: لا أثر على التخزين أو النسخ الاحتياطي
  أو الاستعادة.
- السمة المختارة إعدادات: تغطيها مراجعات الإعدادات والتاريخ والاستعادة
  والتصدير الحالية.
- حزم السمات اللاحقة تعيش تحت جذر البيانات مثل الوسائط والإضافات، فيغطيها
  النسخ الاحتياطي المنسق؛ وتعيد الاستعادة التحقق من المجاميع وتتراجع إلى
  سمة مدمجة مع إشعار للمالك إذا فُقدت حزمة.

## مسار الانتقال من الشيفرة الحالية

صفحة صفحة، كل منها خلف عنوان URL نفسه، مع مفتاح لكل مسار بين توليد القالب
وهيكل SPA (قائمة سماح على مستوى الشيفرة مع تجاوز للمشغّل للرجوع السريع).
تستمر `ResolvePage` ونقاط الواجهة البرمجية وSPA في العمل طوال الوقت، فتكون
كل خطوة قابلة للشحن والتراجع على حدة.

1. **المولّد أولاً:** خط goldmark مع حزمة عيّنات التكافؤ — دون أي تغيير في
   المسارات.
2. **صفحة المقال** (`/{locale}/articles/{slug}`): الصفحة الأعلى قيمة للقراء
   دون JavaScript وللفهرسة؛ وتُشغّل المولّد، والبيانات الاجتماعية (بتوحيد
   تكرار `social.ts` في Go)، وتخطيط السمة الأولى.
3. **الرئيسية، وعني، والكتابة، والبحث:** صفحات ملف شخصي وقوائم؛ ويتراجع
   البحث والمرشحات إلى تنقّل بمعاملات الاستعلام مع جزيرة للبحث الحي.
4. **المجموعات والمخططات** (`/learn` و`/docs` والمخططات): حالات مقفل/قريباً/
   مفتوح على الخادم مباشرة من القرارات الحالية.
5. **صفحات الدروس:** أخيراً، مع جزر التعلم؛ وسلوك التصحيح والتقدم دون تغيير.
6. **إزالة** مسارات SPA العامة و`PublicPage.tsx` وشيفرة العميل المكررة
   للبطاقات الاجتماعية واللوحة؛ وتبقى حزمة لوحة التحكم.

تصبح الخلاصات وخريطة الموقع المراعية للتبويب مباشرتين بعد المرحلة 4 وهما
متابعة مستقلة، لا جزءاً من هذا السجل.

## خطة التسليم المرحلية

| المرحلة | تسلّم |
| --- | --- |
| 1 | مولّد Markdown بلغة Go + عيّنات التكافؤ |
| 2 | بنية القوالب، ومفتاح لكل مسار، وصفحة المقال في السمة الأولى |
| 3 | الرئيسية/عني/الكتابة/البحث؛ وتوحيد بطاقة المشاركة |
| 4 | المجموعات، والمخططات، وصفحات الدروس مع الجزر |

| 6 | (لاحقاً، بآليات القرار 0001) حزم سمات قابلة للتثبيت |

كل مرحلة فرع وطلب سحب مع اختبارات Go مركزة إضافة إلى فحوص المتصفح الحالية
عند 320/390/1280 بكسلاً بالإنجليزية والعربية والفرنسية وفي وضعي المظهر.

## البدائل المدروسة

- **إبقاء SPA وإضافة السمات قشوراً من CSS فقط:** لا تحكم في القوالب، ولا
  قراءة دون JavaScript، ولا قصة للخلاصات/خريطة الموقع، وسيُقيَّد مؤلفو
  السمات بإعادة تنسيق ترميز ثابت. مرفوض.
- **توليد صفحات React الحالية على الخادم عبر Node:** تكافؤ حقيقي مجاناً،
  لكنه يضيف خدمة Node إنتاجية، وهو ما تستبعده البنية المعمارية صراحة. مرفوض.
- **نهج HTML عبر السلك بلغة Go (على غرار htmx) للتفاعلية:** جذاب لاحقاً،
  لكن استبدال تجربة مشغّل الاختبارات القريبة من التصحيح أثناء الانتقال يضيف
  مخاطرة دون فائدة للقارئ. الجزر أولاً.
- **إعادة كتابة كل الصفحات العامة دفعة واحدة:** مرفوض؛ فمفتاح كل صفحة يبقي
  كل خطوة قابلة للتراجع والمراجعة.

## العواقب والمخاطر

- الإيجابيات: قراءة دون JavaScript، ورسم أول أسرع، ومكان واحد (Go) لمنطق
  البيانات الوصفية والبطاقات الاجتماعية واللوحة، ومنصة سمات حقيقية تتكامل
  لاحقاً مع أجزاء صفحات الإضافات (القرار 0001).
- التكاليف: خطا توليد أثناء نافذة الانتقال، وعيّنات تكافؤ تجب صيانتها،
  وتصبح نماذج العرض المواجهة للقوالب سطح توافق لمؤلفي السمات.
- المخاطر: فجوات تكافؤ Markdown (تحدّها حزمة العيّنات ومفتاح التراجع لكل
  مسار)؛ وانحدارات توليد الرياضيات في الصفحات القليلة ذات الرياضيات (يحدّها
  نهج الجزيرة)؛ وأمان حزم السمات مؤجل إلى مرحلته الخاصة بدل حله ضمنياً.
