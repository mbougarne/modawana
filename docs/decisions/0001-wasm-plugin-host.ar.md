# القرار المعماري 0001: واجهة برمجية لمضيف إضافات WebAssembly

[English](0001-wasm-plugin-host.md) · [القرارات](README.ar.md) · [البنية المعمارية](../architecture.ar.md)

- الحالة: معتمد
- التاريخ: 2026-11-01
- صاحب القرار: المالك (مراد بوقرن)
- حالة الترجمة: بانتظار مراجعة لغوية من متحدث أصلي

## السياق

مدوّنة تطبيق من ملف Go تنفيذي واحد وقاعدة بيانات SQLite واحدة، مع مراجعات
Markdown غير قابلة للتعديل، وفرض صلاحيات الوصول في Go على كل مسار
([البنية المعمارية](../architecture.ar.md)). تهدف المرحلة القادمة إلى تحويله
إلى منصة صغيرة قابلة للتوسعة دون الإخلال بهذه الخصائص.

لا توجد اليوم أي آلية للتوسعة، فالتكاملات مكتوبة مباشرة في الشيفرة:

- بروتوكول MCP معالج JSON-RPC في `backend/internal/http/mcp.go` بقائمة أدوات
  ثابتة في الشيفرة تعيد توجيه كل عملية إلى مسارات HTTP الخاصة بأداة النشر.
- اختيار بطاقة المشاركة الاجتماعية في `backend/internal/http/social.go`،
  ومكرر في `frontend/src/pages/public/social.ts`.
- توصيل Notion وجدولة الدروس يقعان في `backend/internal/publisher` ويعملان
  خارج العملية الرئيسية عبر أداة النشر (CLI) ومؤقّت systemd؛ والواجهة
  البرمجية الوحيدة التي تشبه نقطة توسعة في الشيفرة هي
  `publisher.NotionDelivery`.
- لا يملك الخادم أي تجريد للمهام المجدولة، سوى روتين تنظيف واحد يعمل كل
  ساعة، ولا يوجد أي سجل للخطافات (hooks) أو المسارات أو أقسام الإعدادات.

الميزات الرسمية المخطط لها (التعليقات، والمتجر، والشبكات الاجتماعية، ومزودو
الذكاء الاصطناعي) يجب ألا تضيف كل واحدة منها مزيداً من الشيفرة المكتوبة
مباشرة، بل ينبغي أن تكون إضافات مبنية على واجهة برمجية عامة يمكن للأطراف
الخارجية استخدامها أيضاً.

## القرار

بناء مضيف إضافات WebAssembly داخل عملية Go الحالية نفسها، باستخدام
[wazero](https://wazero.io)، وهي بيئة تشغيل بلغة Go خالصة دون أي اعتماديات
(ولا cgo). الإضافات وحدات WASI تُكتب بلغة Go أو TypeScript باستخدام سلاسل
أدوات يوثّقها هذا المشروع ويختبرها؛ ولغة Rust ليست لغة إضافات مدعومة.
لا تحصل الإضافات على أي سلطة ضمنية: كل تأثير يمر عبر دوال مضيف مُدارة
الإصدارات، ومقيّدة بقدرات تعلنها الإضافة في بيان (manifest) يوافق عليه
المالك عند التثبيت.

قبل تشغيل أي WebAssembly، يُثبَت العقد نفسه داخلياً: تُبنى أولاً سجلات
الخطافات والمسارات والمهام والإعدادات بلغة Go عادية، وتُنقل الميزات الرسمية
الحالية (أدوات MCP، وبطاقات المشاركة، وتوصيل Notion، وجدولة الدروس) إليها
كامتدادات مدمجة. ثم يصبح مضيف Wasm طريقة ثانية معزولة لتنفيذ العقد نفسه.

## الحد الفاصل بين المضيف والإضافة

| الطرف | يملك |
| --- | --- |
| المضيف (Go) | HTTP، والتوجيه، والمصادقة، والتخويل، وSQLite، والملفات، والمراجعات، والمعاملات، والجدولة، والأسرار، والتحقق، وعقد البيان |
| الإضافة (Wasm) | المنطق الخالص: معالجة حمولة خطاف، أو طلب موجّه، أو دورة مهمة، أو تغيير إعدادات، واستدعاء دوال المضيف لأي تأثير |

- الإضافة مجلد تحت جذر البيانات: `plugins/{slug}/` يحتوي `manifest.json`
  ووحدة `.wasm` واحدة وأصولاً ثابتة اختيارية. تُسجَّل المجاميع الاختبارية
  (checksums) لجميع الملفات في SQLite عند التثبيت.
- واجهة المضيف البرمجية مُدارة الإصدارات (`host_api_version` في البيان).
  يرفض المضيف الوحدات التي تتطلب واجهة أحدث، ويبقي الإصدارات القديمة قابلة
  للاستدعاء ضمن فترة إهمال تدريجي موثقة.
- لا ترى الإضافات قاعدة البيانات، ولا نظام الملفات، ولا الشبكة، ولا متغيرات
  البيئة، ولا بيانات الإضافات الأخرى. يُهيأ WASI دون أي مجلدات مفتوحة مسبقاً
  ودون أي مقابس شبكة.
- حمولات الخطافات ونتائج دوال المضيف بيانات JSON محدودة الحجم ومُدارة
  الإصدارات (أو بايتات خام للوسائط)، وليست مؤشرات Go أو جمل SQL أبداً.
- يبقى ضبط الوصول في Go. تُطلق الخطافات بعد قرار الوصول الخاص بالطلب؛ ولا
  تستطيع الإضافة توسيع نطاق الرؤية، ولا تجاوز بوابة درس، ولا تغيير درجة
  النجاح، ولا انتحال صفة المالك. يظل جدول الصلاحيات في
  [ملحق عقود الإعدادات ومسارات التعلّم](../architecture-appendix-configurable-learning.ar.md)
  ملزماً لكل مستدعٍ، بما في ذلك الإضافات.

## بيان القدرات

يعلن البيان، ويوافق المالك على، كل ما يجوز للإضافة فعله:

| القدرة | تمنح |
| --- | --- |
| `hooks` | نقاط خطاف مسماة، لكل منها عقد حمولة/نتيجة محدد الأنواع |
| `routes` | معالجات تحت `/plugins/{slug}/…` (عام) و`/api/v1/plugins/{slug}/…` (المالك/الواجهة البرمجية)، يقيّد المضيف معدلها ويفحص صلاحياتها |
| `storage` | تخزين مفاتيح وقيم ومجموعات مستندات JSON ضمن نطاق مسمى مع ترحيلات إضافة ذات مجاميع اختبارية |
| `settings` | مخطط إعدادات محدود تعرضه لوحة التحكم عرضاً عاماً؛ ويتحقق المضيف من القيم |
| `jobs` | مهام مجدولة بتواتر محدود، يشغّلها مشغّل مهام المضيف |
| `http_fetch` | اتصالات HTTPS صادرة إلى المضيفين المذكورين في البيان فقط، بحدود حجم ووقت |
| `secrets` | أسرار مسماة يدخلها المالك، تُخزَّن مشفرة تحت مفتاح المشغّل، وتُسلَّم إلى الإضافة وقت الاستدعاء فقط |
| `content_read` | قراءة الإسقاطات العامة المنشورة فقط (وليس المتون المبوّبة ولا المسودات ولا مفاتيح الإجابات ولا بيانات الاعتماد أبداً) |
| `mcp_tools` | أدوات MCP إضافية، تُوجَّه إلى مسارات الإضافة تماماً كما تعيد الأدوات المدمجة التوجيه اليوم |

يعرض التثبيت والترقية الفرق في البيان؛ وتتطلب القدرات المضافة موافقة مالك
جديدة مع إعادة مصادقة حديثة، مثل بقية الإعدادات الحساسة. التحقق من توقيعات
أرشيفات الإضافات الخارجية مرحلة لاحقة؛ وحتى ذلك الحين يبقى التثبيت إجراء
مالك صريحاً مع تثبيت المجاميع الاختبارية.

## نقاط الخطاف (المجموعة الأولية)

| الخطاف | يُطلق | العقد |
| --- | --- | --- |
| `content.published` | بعد اكتمال معاملة نشر | حدث للقراءة فقط؛ تستخدمه إضافات التوصيل (Notion، والشبكات الاجتماعية) |
| `content.rendered_meta` | أثناء بناء بيانات الصفحة الوصفية | يجوز أن يسهم بقيم بطاقة المشاركة/البيانات الوصفية؛ ويعقّمها المضيف ويحدّ حجمها |
| `page.public_fragment` | أثناء توليد منطقة قالب على الخادم (بعد القرار [0002](0002-server-rendered-themes.ar.md)) | يعيد جزء HTML معقّماً لموضع سمات معلن صراحة (مثل التعليقات أسفل مقال) |
| `job.tick` | وفق جدول الإضافة المسجل | وقت تشغيل محدود؛ يسجّل المضيف النتيجة ويعيد المحاولة بتراجع تدريجي |
| `settings.changed` | بعد تطبيق المالك إعدادات الإضافة | يتيح للإضافة التحقق من الاتصال وتهيئة الذاكرة المؤقتة |

الخطافات ليست مرجعاً للقرار: فشل الخطاف يُسجَّل ويُعرض على المالك، ولا يعطّل
أبداً الحفظ أو النشر أو التصحيح أو تسجيل الدخول في النواة. الأعمال من نوع
التوصيل التي تطلقها الخطافات تمر عبر مشغّل المهام بمفاتيح تكرار آمن
(idempotency)، بما يطابق قواعد التوصيل الموثوق في أداة النشر.

## التخزين والترحيلات

- تعيش بيانات الإضافات في قاعدة SQLite نفسها ضمن جداول يملكها المضيف ومفهرسة
  بمعرف الإضافة (`plugin_kv` و`plugin_documents` و`plugin_migrations`
  و`plugin_installs` و`plugin_jobs`). تحصل الإضافات على واجهة تخزين برمجية،
  وليس SQL أبداً.
- تعلن الإضافة خطوات ترحيل مرتبة ومسماة (دوال Wasm مصدَّرة) بمجاميع
  اختبارية. يسجّل المضيف كل خطوة مطبقة في `plugin_migrations` ويرفض انحراف
  المجاميع أو الرجوع إلى إصدار أدنى — وهو الانضباط نفسه المطبق في
  `backend/internal/db/migrate.go`، ولكن في سجل منفصل حتى يبقى مشغّل ترحيلات
  النواة وترقيمه المتصل وفحص قاعدة البيانات الجديدة دون أي تغيير.
- تعلن المجموعات أحجاماً وفهارس محدودة في البيان؛ ويفرض المضيف حصصاً لكل
  إضافة حتى لا تُنمّي أي إضافة SQLite بلا حدود.

## الإعدادات والأسرار

- يستخدم مخطط إعدادات البيان مفردات التحقق نفسها المستخدمة في
  `backend/internal/siteconfig` (حقول محددة الأنواع، وأطوال محدودة، وتسميات
  مترجمة عبر سجل التسميات). وتعرضه لوحة التحكم عرضاً عاماً — والسابقة هي
  العرض المعتمد على السجل في `LabelsForm` وخرائط `inputSchema` لأدوات MCP.
- إعدادات الإضافات لقطات مُدارة الإصدارات مع تزامن تفاؤلي وتاريخ واستعادة،
  مثل إعدادات الموقع والملف الشخصي والتسميات.
- الأسرار (مفاتيح مزودي الذكاء الاصطناعي، ومفاتيح مزود المدفوعات للمتجر) لا
  تظهر أبداً في اللقطات ولا الصادرات ولا السجلات ولا الحمولة العامة. تُشفَّر
  بتشفير موثَّق تحت المفتاح الذي يحتفظ به المشغّل، مثل بذرة TOTP.

## الأثر على النسخ الاحتياطي والاستعادة

- جداول الإضافات داخل SQLite وملفات الإضافات تحت جذر البيانات، لذا يغطيهما
  النسخ الاحتياطي المنسق الحالي دون أي آلية جديدة.
- يستبعد التصدير المحمول أسرار الإضافات، ولا يجوز أن يتضمن بيانات إضافة إلا
  عندما تعلن الإضافة أن المجموعة قابلة للتصدير.
- تعيد الاستعادة التحقق من مجاميع ملفات الإضافات مقابل قاعدة البيانات
  المستعادة. واتباعاً لعقد الاستعادة، تُبطل أسرار الإضافات مع بقية بيانات
  الاعتماد ويجب إعادة إدخالها؛ والإضافات التي تفقد ملفاتها أو تنحرف مجاميعها
  تعود معطلة مع إشعار واضح للمالك. يُضاف قسم للإضافات إلى
  [دليل الاستعادة](../operations/recovery.md).

## مسار الانتقال من الشيفرة الحالية

1. إدخال سجلات داخل العملية في حزم جديدة (`internal/extension`: الخطافات،
   والمسارات، والمهام، وأقسام الإعدادات، وأدوات MCP) دون أي تغيير في السلوك.
2. إعادة توصيل الميزات الرسمية كامتدادات مدمجة على تلك السجلات: تصبح
   `mcpTools()` قائمة على السجل؛ وتنتقل بيانات بطاقة المشاركة خلف
   `content.rendered_meta`؛ ويحصل الخادم على مشغّل مهام يحل محل روتين
   التنظيف المؤقت؛ ويسجّل توصيل Notion خطاف `content.published` مع مهمة
   توصيل. تستمر أداة النشر (CLI) في العمل؛ وتبقى جدولة الدروس في عملية أداة
   النشر إلى أن تتوفر قدرة `secrets`، ثم تنتقل.
3. إضافة مضيف wazero: تحميل البيان، وتقييد القدرات، وتجميع النسخ، والحدود،
   وواجهة التخزين. تنفّذ الامتدادات المدمجة وإضافات Wasm واجهة Go نفسها،
   فيكون المضيف تنفيذاً ثانياً لا إعادة كتابة.
4. تجميع ميزة رسمية واحدة (بطاقات المشاركة أو توصيل Notion) إلى Wasm
   كإثبات، وشحن سلسلتي أدوات الإضافات بلغتي Go وTypeScript مع مستودع قالب
   واختبارات مطابقة.

## خطة التسليم المرحلية

| المرحلة | تسلّم | تثبت |
| --- | --- | --- |
| 0 | سجلات `internal/extension`، ومشغّل المهام، وامتدادات مدمجة لأدوات MCP وبطاقات المشاركة | ملاءمة العقد للميزات الفعلية |
| 1 | مضيف wazero، والبيان مع واجهة موافقة المالك، وتخزين المفاتيح/المستندات، والخطافات، والمسارات | مسارات شيفرة خارجية معزولة |
| 2 | عرض مخطط الإعدادات، والمهام، و`http_fetch`، و`secrets`، وترحيلات الإضافات | اكتمال سطح القدرات |
| 3 | توصيل Notion وجدولة الدروس كإضافتين؛ وإتاحة أدوات MCP؛ وسلسلة أدوات TypeScript | تكافؤ الميزات الرسمية على الواجهة العامة |
| 4 | إضافة التعليقات (وفق سياسة الإشراف المعدلة)، ثم المتجر، والشبكات الاجتماعية، ومزودو الذكاء الاصطناعي | هدف المنصة |

تصل كل مرحلة على فرعها وطلب سحبها الخاصين مع اختبارات مركزة؛ ولا تصبح أي
مرحلة وعد توافق عام قبل إعلان استقرار واجهة المضيف البرمجية.

## البدائل المدروسة

- **إضافات Go أصلية (حزمة `plugin` أو إعادة التجميع):** لا عزل، وقيود cgo
  والمنصات، وستعمل الشيفرة الخارجية بكامل سلطة العملية. مرفوض.
- **إضافات خارج العملية (RPC عبر عمليات فرعية):** عزل حقيقي لكنه بيئة تشغيل
  ثانية تُنشر وتُراقب لكل إضافة، بما يخالف نموذج التشغيل بملف واحد وخادم VPS
  واحد. مرفوض حالياً؛ وواجهة المضيف JSON مستقلة عن وسيلة النقل، فيبقى هذا
  الخيار ممكناً لاحقاً دون تغيير العقد المنطقي للإضافات.
- **لغة برمجة نصية مدمجة (Lua أو Starlark):** مضيف أبسط لكنها لغة جديدة على
  مؤلفي الإضافات، وقصة قدرات أضعف من WASI. مرفوض: Go وTypeScript هما لغتا
  هذا المشروع أصلاً.
- **دعم سلاسل أدوات Rust للإضافات:** سهل تقنياً (أي Wasm يعمل) لكن كل لغة
  مدعومة سلسلة أدوات موثقة ومختبرة ومصانة. النطاق عمداً Go وTypeScript.

## العواقب والمخاطر

- الإيجابيات: تصبح التكاملات وحدات قابلة للإزالة والتدقيق وبموافقة المالك؛
  وتبقى النواة ملفاً واحداً وقاعدة بيانات واحدة؛ وتتشارك الميزات الرسمية
  والخارجية واجهة واحدة.
- التكاليف: كلفة استدعاء Wasm (مقبولة: الخطافات لكل حدث، لا لكل بايت من متن
  الطلب)؛ وتحويل JSON عند الحد الفاصل؛ وسطح توافق حقيقي تجب صيانته بعد
  إعلان الاستقرار.
- المخاطر: تضخم القدرات (يحدّه جدول القدرات المغلق وموافقة المالك)؛ ونمو
  SQLite بفعل الإضافات (تحدّه الحصص)؛ ونضج سلسلة أدوات TypeScript لبيئة WASI
  (يحدّه شحن السلسلة وتثبيت إصدارها؛ وGo وحدها كافية للمراحل 0–3).
